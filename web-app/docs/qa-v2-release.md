## 实际覆盖

- 未配置后端只有不可用/重试，不提供模拟登录；错误密码停在登录页；密码及 CSRF 不写 LocalStorage。
- 真实 API 请求路径、Cookie/CSRF、金额字符串、权威收款人引用、金额二次确认。
- 转账第一个响应丢失后不显示成功；刷新页面恢复原 `clientRequestId`、金额、收款人及备注；服务返回明确 success 后才显示成功、清理恢复记录并刷新余额和账单。
- HTTP 202 错误信封作为待核对处理；未知余额显示“—”，不会变为 0；游戏节点离线后保留余额时标记上次已知值，并关闭新转账提交。
- 空商城、委托、账单保持空态；公告正文作为受控纯文本处理，不执行 `<script>`。
- 会话退出、手机适配、主题持久化以及公共聊天正常连接状态。

复现：先 `npm run build`，以 `WEB_PORT=5219` 启动本机 `node server.mjs`，再运行 Playwright CLI `run-code --filename=scripts/qa/v2-release.cjs`。脚本会将响应限制在该隔离浏览器环境，不应作为生产脚本使用。

截图位于被忽略的 `output/playwright/v2-release-wallet.png` 与 `v2-release-login.png`，使用动画完成后的画面核对。图片中的 QA 账号和金额属于浏览器测试响应，没有写入发布产物或真实后端。
