## 1. 目标与范围

为 Deuterium IX 提供原生 Android 社区交易/交流、玩家网页及商家/平台管理。当前各端通过同一后端账号与业务服务连接，界面使用自然业务文案，不提供模拟登录或合成余额；列表、权限及资金状态以实际服务端记录为准。

原生 App 四个一级入口为商城、市场、信息、我的。钱包/账单/转账在我的，AI 在信息；委托大厅承接原活动中心入口。网页可按桌面/移动浏览器使用独立导航与管理工作区。

## 2. 视觉与交互

- iOS / HyperOS 方向，主题只有系统、浅色、深色。移除 MD 默认控件外观、动态取色及颜色主题，继续原生 Compose 实现。
- 内容使用清晰分组表面；导航和覆盖卡片使用可关闭的柔光玻璃，底栏/浮层分别开关，材质参数保留。使用“灵动视效”“动态追光”命名。
- 顶部模糊从状态栏连续递减至透明，不能突然变化或生硬裁内容。搜索为独立完整模式，取消后恢复浏览位置并处理键盘。
- 底栏指示器自然位移、弹性与拖动；图标、头像和 AI 背景裁切统一，关闭动效仍有清楚反馈。
- 延续既有付款视觉：模拟扫脸、蓝色圆环和确认勾，覆盖商城、市场、转账、委托预付；不接入真实 Face ID、Apple Pay 或 Mastercard，不采集人脸。真实付款只按权威结果反馈，UNKNOWN 不能显示完成。

## 3. 账号、资料与钱包

- 登录、注册、重置密码使用真实账号和游戏内验证码；原账号主体、UUID 和密码哈希已迁移。当前以 Go/第一方 Deuterium ID 协议为准，账号 [v1](../../../../prd/account.md)保留迁移参考，旧会话和管理权限不自动导入。
- 头像选择、圆形预览、移动/缩放裁切并保存；个人简介可编辑。
- 联系人、公共聊天和私聊头像进入资料，显示上次在线、ID、QQ、简介，提供消息、特别关心、转账。
- 钱包显示可用余额、当天收支、历史账单，支持类型和日期范围筛选。
- 转账支持搜索玩家、最近收款人、金额/备注、确认和失败反馈。钱包转账 [v1](../../../../prd/wallet-transfer.md) 的身份与资金安全边界保留。

App 使用 Bearer，网页使用 HttpOnly Cookie 与内存 CSRF；每次服务端鉴权。游戏 UUID 由可信节点解析，客户端不得指定资金主体。XConomy/Vault 仍是余额权威；DIMA 和 DaoYu 已作为官方收入/冻结系统专户初始化，初始各 0.00、hidden=1，不创建 App/QQ/密码身份。

## 4. 官方商城

- 商品详情含标题、简介、多图、详细介绍、包装内容、交付说明及预计送达；支持搜索、购物袋与加购动效。
- 结算创建独立订单，含商品快照、订单号、金额、时间、交付和状态。
- 通过独立游戏邮箱交付；未领取可按订单规则退款，领取后不可退款。已接入 Core/Mail 合同与状态机，最终配套换包和运行能力已检查；实际玩家客户端领取仍按具体业务验收。
- 当前正式目录没有植入 Apple、NVIDIA、AMD 等早期演示商品；保留的历史品牌素材不代表实际经营内容或售卖现实硬件。
- 商家网页与服务已提供店铺、分类、品牌、商品草稿/发布、库存和 Core 批准模板管理；实际店铺与商品由有权限的用户创建。

商品发布冻结交付模板。报价和下单共用整单数量、跨店、库存域、共同领取节点与金额限制；不发出必然无法交付的组合报价。下单再次核对公开版本、价格和库存，保存不可变成交及邮箱快照；后续模板/价格编辑不改变已付款订单。业务接口不接受原始 NBT、任意命令或客户端自报收款人。

## 5. 市场与担保订单

- 双列浏览；分类为建材、装备、补给、装饰、建筑服务、其他。再次点击已选分类取消浏览筛选，发布必须选择一个具体分类。
- 发布含标题、简介、详情、价格、库存 1–999、最多 5 图（第一张封面）、交付方式及必要联系方式。支持封面调整/删图，下架二次确认，重上架回预填表单重新校验。
- 普通商品选择送货上门或约定自取并填地点；建筑服务填写项目与工程地点。
- 买家付款冻结，确认收货/验收或到期后才结算卖家。未发货不能确认，手动确认需二次确认。
- 普通商品发货后 72 小时自动确认。建筑服务从开始施工按卖家工期计时，提醒工期包含验收预留。
- 建筑状态为待开工 → 施工中 → 已完成待验收 → 已验收；完成不重新开始总工期。
- 我的订单区分商城/市场及市场买入/卖出；成交快照不随商品编辑改变。详情提供 QQ 复制、私聊、进度、资金状态、确认和退款。

退款：未发货立即退款；已发货仅能申请一次，提交前二次确认并等待卖家处理。拒绝/撤回不恢复次数；拒绝必须填理由并通知买家。处理中暂停自动确认，拒绝/撤回后恢复剩余时间，同意后返款并结束计时。完成订单不能退款；退款、确认和到期处理不能重复付款或返款。

平台介入已从契约进入真实服务与管理网页：支持申请、补充证据、撤回、管理员受理、要求资料和裁决。依据冻结交易与当事人提交的资料；聊天证据由本人选择可访问的消息引用，提交前明确交易双方和管理员的可见范围，不信任客户端自报正文、作者、订单或金额。

资金仍在执行或核对时暂停二次资金操作；部分退款/余款结算分别保留进度，不重复已成功步骤。普通“找不到邮件”不构成退款证明，未创建交付必须有持久取消屏障。严格规则见[邮箱取消契约](../../../../contracts/mailbox-cancellation-core-v2.md)。

## 6. 委托大厅

- 替换活动中心；顶部发布/我的委托，后者区分发布/接取。
- 发布填封面、标题、说明、地点、紧急程度、履约时限、报酬。预付并冻结全部报酬成功才进入待接取。
- 仅一名其他玩家接取，本人不能接自己的委托；从接取起计履约期限，锁定报酬和约定。
- 提交完成后进入待确认，发布者有独立 72 小时验收期；主动确认或到期只结算一次。
- 履约超时标记逾期、提示沟通，不将未完成工作自动结算。
- 待接取可确认取消并退预付；接取后取消/退款遵循双方协商与一次申请边界，争议走平台接口。

建筑订单总工期与委托提交完成后的 72 小时验收是两套规则，不能混用。

## 7. 信息与通知

- 信息页包含公共聊天、按联系人隔离的私聊、AI、公告、委托。旧聊天 v1 的公共互通范围不能用来移除新版私聊/AI。
- 单击头像资料、长按头像提及、输入 @ 显示自然过渡候选；特别关心及提及有提醒。
- 公共/私聊支持复制、回复和人工转发，含可取消引用预览与已发送引用卡片；原消息不可见时有明确降级。私聊每次检查会话成员，不因消息编号或转发目标绕过权限。
- 通知为分组业务偏好页并通过服务端持久化，业务开关与系统权限分开，覆盖交易、提及、特别关心；不以“体验一条通知”为主要页面。
- 交易通知按接收人隔离，买方可看拒绝退款理由；公共提醒、私聊和通知使用真实服务。系统推送权限与所有后台/跨设备送达场景仍应分别验收，不能由一次连接成功推断全部通过。

AI 使用 DeepSeek V4 Flash 与按需原生联网搜索，免费 20 次/24 小时，平台管理员免次数额度；其余套餐显示 `9999999.00` 且禁购。SSE 正文、来源、历史、`/new` 和同请求恢复均走服务端，供应商 Key 不进入客户端。来源标记与正文链接区分，不伪称链接已经核验。

## 8. 应用与资源更新

关于页采用系统更新式布局，区分应用/资源版本，含检查更新、可用更新红点、真实下载字节/百分比、取消/重试和下载后操作。

全量为 APK 地址；资源包仅图片、文案、配置，不运行代码。校验 HTTPS 来源、大小、SHA-256；APK 还校验包名、签名、版本，交由系统确认安装。资源包校验兼容版本与路径，验证后原子切换，失败保留旧资源。

当前更新地址已配置并实际发布 APK 20003；公网完整下载、大小/哈希/签名/版本核对通过，旧版本可发现更新、20003 不提示自身更新。资源更新的规则保留，但本轮未发布可执行代码资源包，不能把早期资源演练当成本次远程资源发布。

必须定义角色权限、校验、状态动作、错误、分页、乐观锁、幂等、未知结果查询、超时、事件、审计和资金权威。保留已有账号/钱包/聊天接口，不能假设旧转账已支持冻结账本。

当前详细契约、Go 交易状态机和相关 App/Web 界面已经实现并发布；具体路由、响应扩展及测试范围见[交易验收](../../../../qa/commerce-v2-2026-09-08.md)与[项目索引](../project-status.md)。真实数据库并发/回滚、可控 RPC、隔离 Youer、浏览器只读、模拟器和实服测试是不同证据，不合并为“全功能实机通过”。
