# 官方管理端玩家成交与逐笔交易查询增量

2026-09-08。用户已要求：统一官方管理站能查看每位玩家的已出售金额、每笔交易。**本文件为待后端实现的只读契约；Foundation 8db1109 不包含这些能力。** 不改写其已验收状态。

机器定义：[OpenAPI](openapi-web-admin-commerce-read.yaml)。已有公告管理继续复用新版 App 契约的 `/admin/announcements`、单公告 PUT、publish/unpublish；不要新建第二套公告接口。网页编辑正文在正式接入时映射到受控 ContentBlock，而不是直接存储或执行 HTML。

## 权限

- 本任务的“商家端”指统一官方管理网站；不因此给普通店铺成员全玩家审计权。
- 建议新增权限 `commerce.audit`（待与后端统一），与只读 `core.read`、商家订单权限分离。所有列表、统计、明细、导出都由服务端校验。
- 普通商家继续使用 `/merchant/orders` 查看获授权店铺订单；普通玩家继续看本人订单。不能靠前端隐藏列或传入 admin=true 放大范围。
- 每次访问重要交易资料留审计；响应使用 `Cache-Control: private, no-store`，不得进入共享 CDN 缓存。无权访问对象按既有契约统一 404，未登录 401。

## 统计定义

每位玩家的**商品销售**只包含其作为卖方的玩家市场订单；委托报酬与转账另有渠道，官方商城购买不会变成该玩家销售额。

- `grossSalesAmount`：已付款成交原额。未付款及付款前取消不计。
- `refundedAmount`：有权威成功回执的实际退款，包含部分退款。仅提出申请不算已退款。
- `netSalesAmount`：`grossSalesAmount - refundedAmount`，网页显示“净出售金额”。包含尚未释放的担保，不能称为已到账收入。
- `settledAmount`：已实际结算给卖方的金额；资金处理中不计已结算。
- `heldAmount`：当前仍由担保持有的剩余金额；部分退款后不能继续显示原冻结额。
- `paidOrderCount`：该范围内发生过付款成功的订单数；全额退款仍保留历史成交次数。
- `unknownOperationCount`：存在未查明资金结果的记录数；不将未知状态伪造为 0 元已结算。

统计基于后端权威账本与订单快照，按全部匹配记录计算。不能只汇总当前分页，不能把账户余额或前端 localStorage 当来源。单个响应的行、总计、过滤范围与计算时刻一致；客户端切换筛选或收到游标失效后重新查询，不拼接不同范围的统计。

日期参数为 UTC ISO 8601：`from` 包含，`to` 不包含；网页按用户本地日历选择日期并换算。金额为信用点十进制字符串，禁止浮点运算。记录中的资金字段若尚未知允许 null，并配合明确状态展示。

## 接口

基础路径 `/api/v1`。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /admin/commerce/players` | 按游戏名/QQ、成交日期筛选账号销售统计，游标分页，含全部匹配范围的总计 |
| `GET /admin/commerce/players/{playerRef}` | 单账号销售汇总、计算范围和权威身份，用于直接打开档案 |
| `GET /admin/commerce/transactions` | 全站或指定 playerRef 的逐笔交易，支持身份、渠道、状态、日期、关键词与游标 |
| `GET /admin/commerce/transactions/{transactionRef}` | 在同一授权范围内取得单笔详情及不可变成交摘要；transactionRef 为全局不透明引用 |

逐笔交易涵盖官方商城、玩家市场、委托、转账，保持每笔业务一条记录；不能把双方账本分录重复算成两笔业务。返回付款方、收款方、渠道、业务原状态、付款/退款/结算/担保金额、创建时间和关联资源引用。未接取委托的收款方为空。

支持 CSV 导出时必须沿用相同权限、筛选和全部匹配范围。后端可以复用分页查询完整遍历，或追加流式导出；当前页导出必须明确命名为当前页，不能冒充完整账目。对非可信文本防护电子表格公式注入。

## 后端验收要求

普通玩家和仅有店铺权限的账号被拒；付款前取消不入销售额；部分退款准确扣除；处理中/UNKNOWN 不计已到账；委托/转账不污染商品销售；一个账号的汇总与同条件明细可核对；游标翻页不漏/重业务；列表与详情不泄漏无权限玩家；导出与筛选一致；日志不记录 Cookie 或 CSRF token。
