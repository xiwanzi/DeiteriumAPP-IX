# 后端需要各端提供什么

2026-09-08。这是新后端开发对接入口；计划、草案与已实现必须以本工作区实际验收报告区分。**用户最新明确：邮箱保留独立插件，Core 不包含邮箱；用户将按本契约修改邮箱。Core 只实现公开 API 适配，不读写邮箱数据库。**

| 对接方 | 需要提供／修改 | 后端保证与限制 |
| --- | --- | --- |
| Android | 沿用 `/api/v1`；身份用 userId/playerRef；所有交易使用稳定幂等键；事件后查权威详情；图片直传 OSS | 不接受客户端自报 UUID、余额、订单归属；现有体验状态不直接上传为真实订单 |
| 玩家网页 | 同域 Cookie 会话，CSRF header；WebSocket 使用 Cookie＋Origin 校验；禁把长效令牌放 URL 或 localStorage | 与 App 共用账号和业务；网页会话响应不返回 Bearer token；客户端同时在线不复制交易状态机 |
| 官方管理端 | 权限决定页面；商品发货选择 `itemRef + revision + quantity`；明确展示可领取服务器；支持申诉列表和审计 | 管理端不能提交任意 NBT、游戏指令或自报退款金额；商品发布要验证附件快照及权限 |
| Core 节点 | serverId、独立密钥、能力版本、持久化出站事件、ACK 后清理、重连重投 | 后端以认证配置决定来源；相同 eventId 不同内容拒绝；缓冲满时断开补传 |
| TrChat／聊天适配 | 采集审核通过的本服原始公共消息；过滤私聊与桥接回显；保留来源 ID | 游戏消息汇入 App 公共频道；现有 TrChat 负责游戏服间互通；App 消息每个目标服一次，不能再由 TrChat 扩散 |
| 物品库 | 不可变模板版本、原始内容 SHA-256、安全预览元数据、所需模组/组件、兼容服范围；按版本解析 | Web 不读取或反序列化原始物品；已成交版本必须保留，不因模板更新重发不同内容 |
| 邮箱 | 全网共享收件与领取记录；deliveryId 幂等投递；query/revoke/claimed 事件；serverId 白名单；与 claim 互斥的撤回 | 后端只有收到权威未领取且已撤回结果才退款；超时 UNKNOWN 不重发物品 |
| YouerModSync | `loadSucceeded`、当前登录/切服代次、领取期间保存/切服屏障、`saveSucceeded`、失败状态 | 清除“同步中”不代表成功；固定等几秒不能代替屏障；不成功就拒绝领取 |
| XConomy/Vault 适配 | 精确 decimal 金额、原操作查询、受控 reserve/release/refund、可恢复执行日志 | 不把普通 withdraw/deposit 拼接称为原子担保；如果没有可核对结果，禁用真实资金入口 |
| 未来应用 | 注册 clientId、精确回调地址、scopes；使用统一 Deuterium ID 授权 | OIDC Code＋PKCE 接入同一账号；不会要求每个应用各自复制账密 |

## 商品到邮件的完整数据流

1. Core 物品库发布不可变版本及安全元数据，后台查询并选择附件。
2. 管理员保存发货模板：附件列表、单件数量、允许领取 serverId 列表、模板 revision。
3. 商品上架前验证所有模板可解析，领取列表有兼容节点；保存审计记录。
4. 玩家购买时，后端验证库存、价格、身份并冻结订单和发货快照；每种附件最终数量为商品数量乘模板数量，执行上限检查。
5. 付款权威成功后，后端落库 deliveryId 和邮件创建命令；Core 按同一 deliveryId 查询/创建，实际邮件保存快照及禁领范围。
6. 玩家在允许且同步就绪的子服领取；Core 先持久化领取执行身份，操作背包，协调保存，记录结果后产生 claimed 事件。
7. 重试、断线和重启均查原记录。未领取订单退款先撤回邮件；领取、撤回只能有一个胜者。

详细身份协议见 [统一登录与网页](deuterium-id-web-v1.md)，游戏通信见 [Core 协议](deuterium-core-v1.md)。
