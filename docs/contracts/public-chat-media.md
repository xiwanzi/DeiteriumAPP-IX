## 已确认产品边界

- 公共聊天支持 Unicode Emoji、单张图片、GIF 和自定义静态/动态贴纸；一次只能选一张，没有原图、画质或批量发送选项。
- 所有输入媒体在 App / Web 客户端处理和压缩，服务端校验格式、指纹、资源开销及权限，不承担常规转码。
- 个人贴纸库按账号云端同步，静态和动态合计最多 10 个；满额必须手动删旧再加新，重复收藏不占新名额。导入保存压缩版本。
- 普通媒体每条消息自发送成功起可从服务器读取 72 小时；未发送上传文件也只保留 72 小时。读取不续期。
- 内容完全相同的压缩文件通过 SHA-256 去重，复用对象，不合并独立消息。每条消息的到期时间独立，物理对象等最后一个有效引用/收藏释放后清理。不存在有效对象时重新上传。
- 云端贴纸收藏为长期引用；删除个人收藏不删除他人收藏、历史消息或本地已缓存媒体。
- 数据库永久保留文字及消息元数据。用户已选择玩家补拉最近 30 天，不影响数据库保留与本地旧记录。
- App 新增独立聊天缓存：记录、聊天图片、贴纸及缩略图合计最多 500 MiB，不按时间过期；先淘汰最早缓存的媒体（查看不改变顺序）。单独保护待发送队列。媒体与其他业务图片不重复计费/保存。
- 本地文件优先于服务器过期状态；只有缩略图则保留预览，清晰图缺失且服务端过期时提示。换机/清理后不能恢复过期普通图片。
- 清理提供“仅清理聊天媒体”“清理聊天记录及媒体”；不删除云端文字或贴纸库。记录缓存本身达到预算时才从最旧记录收缩，保证总容量上限。
- 点击发送立即出现本地预览，后台串行压缩、上传和提交；轻量等待/失败重试，不展示 OSS、上传百分比或内部校验术语。重试沿用原幂等键，未知结果先查询/复用。
- 表情面板与键盘互斥，保留光标/草稿/引用；Emoji 插入，贴纸点击即发、长按预览。已在历史位置时不强制滚底。
- 查看器从缩略图展开，双指缩放、双击还原/放大、边界移动、基础比例拖动关闭，关闭动效时降级；长图阅读优先于关闭手势。
- 游戏仅保留文字/Emoji 转发，图片为 `[图片]`，贴纸为 `[贴纸]`。不扩展游戏头像、私聊或多媒体渲染。

## 工程与验证

沿用 Go 身份/幂等/游戏投递、Rainyun S3 签名直传和 App 现有 Compose/Coil。媒体资源单独记录消息引用及收藏授权，不能通过猜测 hash 获得私有或未发布内容。并发新增收藏在账号锁内校验 10 个上限；回收与新增引用互斥，禁止回收中对象再次绑定。

新增数据库迁移，不改旧迁移。上线前备份数据库，回退程序不回滚生产数据；媒体前缀与旧商城/头像资源隔离。开发不触碰生产配置或业务数据。

验证：并发去重/满额、所有权与跨账号访问、每消息 72 小时及最后引用回收、原请求恢复、永久文字与有限查询；App 500MiB 淘汰、离线/过期本地查看、两种清理、待发送隔离；单图选择、透明贴纸与动图时序、键盘/面板和查看器手势、浅深色/动效关闭、Web 与游戏摘要。

## 实际接口与资源模型

全部接口沿用 `/api/v1` 身份认证和 Web CSRF。Web 媒体请求携带 `X-Deuterium-Actor`，与当前 Cookie 身份不符返回 `ACCOUNT_CHANGED`，防止跨标签页切换账号后把旧队列发到新账号。

| 方法及路径 | 用途 |
| --- | --- |
| `POST /chat/media/uploads` | 提交稳定 `clientRequestId`、压缩主图/缩略图 SHA-256、标准 Base64 MD5、字节数；可复用时直接返回 READY，否则给两份受约束 PUT 授权 |
| `GET /chat/media/uploads/{id}` | 同一上传的状态/授权恢复；仅创建者可读 |
| `POST /chat/media/uploads/{id}/complete` | 有界校验 WebP 字节、指纹、实际尺寸与每个动画帧，完成全局字节去重 |
| `GET /chat/media/files/{id}/access?messageId=...` | 按消息自己的期限签发读取链接；无 messageId 时只允许自己的有效上传或个人贴纸 |
| `GET /chat/stickers` | 当前账号最多 10 个收藏及资源描述 |
| `POST /chat/stickers` | `{mediaId}`，原子检查名额，重复收藏幂等 |
| `DELETE /chat/stickers/{id}` | 仅移除自己的收藏，释放名额，不修改别人的收藏与消息 |
| `POST /chat/messages` | 原消息协议增加可选 `media: {mediaId,type}`，type 为 image/sticker；服务端生成 `[图片]`/`[贴纸]` 摘要 |
| `GET /chat/sends/{clientMessageId}` | 当前账号原发送结果，用于未知回执恢复，不创建消息 |

消息、WebSocket、游戏投递及通知只携带元数据/文字摘要，不传二进制或 Base64 图片。消息资源描述包括 ID、主图/缩略图指纹、字节数、宽高、动画属性、类型和消息截止时间；临时授权 URL 不写入历史记录。

`chat_media_objects` 保存不可变资源及 canonical_hash；该唯一键只取主图 SHA-256，缩略图编码变化不会导致同一主图复制。只有自己的有效授权或仍可见的公屏消息允许免上传复用；不能凭私人资源的指纹直接获得访问权。无既有权限的相同字节需先完成上传验证，再归并到同一资源。并发验证可能产生短期暂存副本，副本仍被跟踪并按 72 小时回收，不成为重复的长期资源。

`chat_media_uploads` 保存请求幂等及三天授权；`chat_stickers` 为永久收藏引用；`public_chat_media` 为每条消息的独立三天引用。回收先锁定并标记 DELETING，再删除两种文件，失败可重试；新上传使用新对象 ID，旧清理不会误删重建文件。聊天对象使用独立 `chat-media/` 前缀，不进入旧业务素材的 30 天回收流程。

主图及预览都使用 WebP。Android 静态像素使用平台编码器，GIF 解码使用 Glide 的独立 gifdecoder 模块；Web 在 Worker 中使用 libwebp WASM 和 gifuct-js。动画容器按 WebP RIFF 规范封装全画布帧，保留时间与循环，避免引入整套视频运行时。动画最多 30 秒、300 输出帧；较长动画相应降低采样帧率，但不加快播放。输入文件最大 20MiB，动画额外检查原始画布/帧像素预算；服务端校验队列限制为单并发。上传准备请求暂设每账号每天 200 次，消息发送沿用已有频道限频。

相同源图在同一编码实现内稳定输出，重试复用已编码文件；不同系统编码器产生不同字节时不做视觉相似去重。非常小且已经高效编码的 GIF 转 WebP 后可能略增大，不能保证固定百分比压缩。

## App 本地与界面

聊天记录按服务来源、账号、稳定会话 ID 隔离，SQLite 保存记录，文件按内容指纹保存；游戏昵称不作为私聊缓存身份。清理仅影响本机，队列放在独立受保护目录。数据库记录优先保留；只有记录本身也占满总预算时才收缩最旧本机记录。清理记录会同步清空当前会话内存展示，注销记录仍遵循既有账号清理规则。

图片展示先读本机，再请求云端。默认先缓存预览，点击后缓存清晰图；因此只有预览且主图已经云端到期时，保留预览并说明清晰图无法恢复。图库缩略图之外的普通头像、商品图仍使用原图片缓存，不能重复计入聊天缓存。

App 队列归属于账号会话，离开聊天页继续处理；Web 队列归属于认证客户端并持久化 IndexedDB，路由切换只解除界面订阅，退出/切号停止旧账号任务。两端均保留稳定消息 ID，回执未知时核对原请求。发送者将已确认的本地处理结果直接放入缓存。

当前媒体入口限公共聊天；现有私聊文字的本机缓存和 30 天远程历史读取一并接入，AI 会话协议保持。媒体支持回复及添加到贴纸；不把媒体转发到尚未支持附件的私聊。普通文字复制/转发保留。

## 发布及回退约束

新增迁移 `036_chat_media.sql`，不改旧迁移、不清理既有业务数据。先部署兼容旧客户端的 Go 及迁移，再发布 Web/App。旧客户端和游戏继续显示文字摘要。正式发布需要另行递增客户端版本，本机验收包不是线上更新。

回收由新 Go 每分钟执行；对象达到期限后按引用判断删除，元数据与文字不按时间清除。不得给整个聊天对象前缀直接套“创建满三天删除”的 OSS 规则：这会误删仍有新消息引用或已收藏的贴纸。

若回退旧 Go，新媒体入口与自动清理会停止；保留新增表和对象，前滚修复后继续回收，不恢复旧数据库覆盖新增消息。若部署站点设置额外 CSP，需允许本站 Worker 和 WASM 编译，并正确提供 `.wasm` 文件；S3 的既有签名 PUT/GET CORS 规则沿用。
