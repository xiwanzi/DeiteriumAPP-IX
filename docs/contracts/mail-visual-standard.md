2026-10-04 称呼统一：自动工单回执、人工工单回复及人工支持邮件的发件人名称均为 **Deuterium IX 玩家支持**，共用同一个名称常量。邮件联系标签和管理页面也使用“玩家支持”，不再混用“客服”或“客户支持”。邮箱地址、通知用途、个人署名及既有版式保持。已发出的历史邮件不重写。

## 品牌与阅读规格

- 标准徽章 **48 × 48px**，品牌间距约 16px。
- 字标按官网 Geist 650、21px 视觉字号生成透明双倍清晰度 PNG，邮件以 **143 × 26px** 显示。深浅底各一份，与原徽章一起通过固定 HTTPS 地址加载，不作为 MIME 图片附件发送；不让邮箱客户端重新选择字标字体。
- 联系说明 **12px**，版权 **11px**；颜色保持可读，不用过小、过淡的字压低视觉重心。
- 客服正文优先，工单编号仅作顶部轻量标识，署名紧随正文，品牌页脚与正文自然分开。自动回执不显示「待审查」。
- 验证码继续是真实文字，保留复制、搜索、无障碍与纯文本版本；不得为了固定字体而把整封正文或验证码转成图片。
- 保留各邮件的用途和原配色：简洁的验证码 / 客服邮件，与既有终末地审核邮件分别排版；字体和品牌资产统一。

## 实现约定

- 共用 `templates/mail-fonts.css`、`mailHTML` 与固定的 HTTPS 品牌图片地址，新模板不能重新选择通用字体作为主字体。
- 覆盖注册、找回密码、更改密码、审核通过/未通过、工单回执、人工回复，以及原纯文本的管理/系统通知和内部转交邮件。纯文本备用内容和投递元数据保留。
- 未自带 HTML 的消息经 `RenderSystemMessage` 包装，已经排版的邮件不重复加页脚。
- 手写正文只做安全转义，不改写用户内容。回复地址、主题、线程标记、权限、内部备注隔离及消息幂等沿用业务逻辑。
- 字体资源引用不能包含收件人、验证码、工单号等查询参数。

## 客户端边界

HTML 邮件不能强制所有客户端接受外部字体。Gmail 等客户端对 `@font-face` 有限制；正文按声明的本地鸿蒙 / 微软雅黑 / 苹方等字体回退。客户端允许加载图片时，徽章与字标保持官网字形。纯文本阅读模式由客户端决定字体。

依据：[Gmail CSS 支持文档](https://developers.google.com/workspace/gmail/design/css)、[Can I email 的字体加载实测](https://www.caniemail.com/features/css-at-font-face/)。浏览器预览不能当作 QQ、Gmail、Outlook 实际投递验收；必须如实区分正常加载和回退效果。
