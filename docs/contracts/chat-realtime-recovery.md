# 聊天实时推送与历史恢复

2026-10-13 本机候选，尚未发布。对应[计划](../plans/chat-delivery-recovery-20261013.md)。

## 现有接口的兼容扩展

`GET /api/v1/chat/ws` 沿用原会话认证。新 App 发送 `X-Deuterium-Private-Chat: 1`，才会收到自己所属会话的私聊消息；未携带此头的旧客户端继续只接收原公共聊天事件。游戏专用 token 仍禁止使用此端点。

私聊复用 `chat.message` 包装，`payload.message` 与私聊 HTTP 历史中的消息一致：`kind=private_chat`、`conversationId`、`messageId`、`clientMessageId`、`sender`、`content`、`sentAt`，以及可选的 `media`、`reply`、`forwarded`。客户端按 `kind` 路由，不能并入公共聊天。

服务端从会话成员表筛选消息，接收方与发送方的其他设备均可同步，第三人不可读取。写入后原有 Hub 唤醒即时扫描，周期查询继续兜底；每批最多 50 条，满批主动继续扫描。连接建立时取得当前游标，连接之前的遗漏由 HTTP 补拉恢复，不把推送当作历史存储。

## 客户端恢复规则

- WebSocket 每 10 秒主动 ping，失效后从 1 秒开始退避重连，最长 15 秒；重连不等待额外 `/account/me` 请求。
- 回前台或默认网络恢复时重建连接并立即补拉；公共聊天页面进入时立即同步，前台每 5 秒兜底。私聊原轮询保持兼容。
- 公共及当前私聊按上次成功同步位置分页补齐断线缺口，以消息 ID 去重。实时包或会话摘要不推进“已完整补拉”的位置，避免最新一条先到就跳过中间消息。
- 旧连接停止后的迟到回调不能更新新连接状态；未知发送结果继续沿用原请求标识。

## 游戏消息显示

附近文字、图片、贴纸统一按原始 `sentAt` 满 300 秒失效。客户端 tick 清理并通知视图更新，读取列表也过滤过期项；延迟包、重载历史不会重置计时。服务端附近历史采用相同的五分钟查询窗口，团队仍为 30 天。本轮不物理删除数据库消息或图片对象。

所有游戏聊天列表按完整发送时间排序；等时消息保持稳定顺序，历史仍不进入实时 HUD。1000 条缓存上限淘汰发送时间最早的一条，避免历史后到挤掉新消息。
