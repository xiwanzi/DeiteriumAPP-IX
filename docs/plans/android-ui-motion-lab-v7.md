## 界面与配置

- 所有付款（商城、市场、转账、委托预付）先显示模拟扫脸动画，连续衔接蓝色圆环和确认勾。没有摄像头权限，不采集人脸；减少动态效果时提供简短静态反馈。
- 市场分类缩减为建材、装备、补给、装饰、建筑服务、其他六类；浏览时再次点击已选分类取消筛选。发布只选择具体一类，旧细分类映射到新类别。
- 活动中心替换为委托大厅。顶部提供发布和我的委托入口；我的委托区分发布/接取。发布包括封面、标题、说明、地点、紧急程度、履约时限和报酬；发布时预付并冻结全部报酬。
- 市场建筑状态补为待开工 → 施工中 → 已完成待验收 → 已验收。完成动作不重置此前从开工开始的总工期，继续尊重“工期包含验收预留”的已确认规则。
- 拒绝退款必须填写理由，持久化并向买方展示和通知。一次退款机会规则保留。平台介入只定义申请及管理端处理接口，不在 App 新增介入表单。
- 普通商品和工程/委托倒计时统一为紧凑、等宽数字和轻量进度的样式，暂停/超时/等待确认有清楚文案。
- 主导航、公共聊天、公告和委托使用统一的精细图标；AI 图片与背景使用相同圆形裁切。
- 用户追加：公共聊天与私聊长按消息支持复制、回复。回复带可取消的引用预览和已发送引用卡片；契约补充被回复消息标识、服务端引用快照和原消息不可见时的处理。
- 用户再次指出顶部模糊存在明显分界。本轮必须重做整个过渡曲线，使模糊覆盖和底色从状态栏起连续递减、下沿平缓归零，不能保留前版高不透明平台后快速消失的曲线。滚动录屏检查真实素材经过顶部时的连续性。
- “液态玻璃”改名“柔光玻璃”，底栏和浮层分为两个独立开关；模糊、透明、折射、高光等材质调节保留。“界面动效”改为“灵动视效”，“随角度变化的高光”改为“动态追光”。
- 改密、转账、付款等覆盖在原页面上的卡片使用可关闭的柔光玻璃；主内容文字保持清晰可读。顶部渐变规则保留。
- 通知改为正式偏好页，分组开关控制系统提醒偏好并本机保存；系统权限与业务偏好分开，不再以“体验某条通知”为主要页面内容。

## 委托状态与资金

用户明确采用：从接取起计算履约时限；接取者提交完成后，发布者有 72 小时确认，到期自动结算。

1. 发布预付成功后进入待接取，资金冻结；失败不能发布，重复提交不得再次扣款。
2. 只允许一名其他玩家接取；本人不能接自己的委托。接取后进入进行中，快照锁定报酬和约定，不再无条件编辑或撤销。
3. 接取者提交完成说明后进入已完成待确认，启动新的 72 小时验收期。履约超时仅标记逾期并提示沟通，不把未完成工作自动结算。
4. 发布者确认或验收期届满，只结算一次给接取者。待接取时可确认取消并原路退回预付；接取后的取消/退款复用双方协商与一次申请边界，争议交由平台接口处理。
5. 本机钱包、委托、交易通知与市场状态共同保存，升级兼容 v6 记录。正式后端必须使用事务/受控经济操作和可核对的冻结账本，不能假设现有转账接口已经支持担保。

## 更新

关于页采用系统更新式布局，区分应用版本和资源版本，检查更新、可用更新红点、下载字节/百分比、失败重试/取消、下载后操作。全量是 APK URL；资源包只允许图片、文案与配置，不下载运行代码。

下载与校验器按真实文件流程实现：HTTPS 地址、大小和 SHA-256 校验；APK 校验包名、签名及版本后交给 Android 安装确认；资源包验证兼容版本、文件路径与大小限制，完整校验后原子切换，失败保留旧资源。没有实际更新服务时清楚显示本机体验状态，提供可验证的资源样例，不伪造已安装新 APK。

接口文档定义更新服务与发布管理。尚未提供生产更新地址，所以本轮不声称已连接正式更新服务；真实 APK 下载/安装路径用本地测试服务与测试升级包验收。
