# 商城大目录修复（2026-10-08）

2026-10-08 后续状态：本候选已随 App 2.0.19 / Web 2.0.28 上线，见[发布记录](../deployment/deuterium-2.0.19-live.md)。下方保留发布前候选的验证范围。

本轮处理 3,084 件商品批量发布后暴露的网页库存误判、App 首屏等待和图片滚动加载问题；保留现有视觉，后续大规模 UI 改版另行处理。当前基线为 `4590afe`，App 2.0.18 / Web 2.0.27。独立工作区 `catalog-scale`，不覆盖其他工作线。

## 已确认边界

- `inventoryPolicy=UNLIMITED`、`availableStock=null` 表示不限库存，不能回退到内容中的 `stock=0`。有限库存的实时 0 仍须禁购，成交仍由后端报价和库存事务判定。
- 商城首屏按页展示，后续随滚动提前加载。分类及搜索在服务端查询完整目录；购物袋独立读取关联商品，不能把未载入商品判断为下架。
- 图片复用当前账号获授权的业务图片地址、现有磁盘缓存和完整性校验，预取可视区之后的有限窗口。不得为了提速公开私有 OSS、下载全部原图或削弱账号隔离/过期逻辑。
- 后端商品列表批量读取图片元数据和绑定，减少每商品重复 SQL。单张不可用图片降级展示；数据库等整体故障仍明确报错，不能伪装空商城。
- 查询切换、离开页面和账号切换的过期请求不得覆盖新结果；普通取消不展示红色业务错误。续页失败保留已读商品并允许重试。
- 用户随后确认偶发红字与 `The coroutine scope left the composition` 相符；已从当前 Compose 1.10.3 的 `LeftCompositionCancellationException` 核实该原文。旧版 `refreshStore` 的 `runCatching.onFailure` 把离开页面的正常取消写入 `shopError`，本轮分页器重新抛出取消，不作为业务失败。
