# Deuterium Core 1.0 开发与验收

2026-09-08，用户本轮明确要求：主命令 `/dc`；不存在需要迁移的旧物品库存档；物品库必须内置 Core，完整开发可运行插件；邮箱仍为独立插件。此前只交付后端基础版不满足本轮目标。

## 工作范围

在独立 backend-rewrite 分支新增 Java 21 的 `deuterium-core` 插件，目标 Youer/Minecraft 1.21.1。Core 自己负责物品库、节点身份、远程通信、原始公共聊天采集、玩家目录、受控游戏操作与邮箱 API 适配。保持 `Deuterium-Mail` 独立，不读写其数据库，不把其实现打入 Core。

实际核对的邮箱开发版为 0.6.0，已提供 `MailboxIntegration`、`MailboxItem` 与 `MailPlayerDataBarrier`。物品载荷 codec 为 `bukkit-bytes-v1`，与 `ItemStack.serializeAsBytes/deserializeBytes` 一致。Core 编译引用其公开 API，JAR 不包含邮箱 API/实现类；最终再次核对接口变化。

App 的最新契约与本地快照相比仅修改 AppearanceSettings，与本次 Core 消息和物品格式无冲突。网页任务已确认 chat.deuteriumix.com 与 api.deuteriumix.com 域名方向；未备案期间不擅自部署或降低真实凭据的 TLS 要求。

## 必须完成的功能

1. `/dc save/get/give/info/list/versions/archive/restore/policy`：权限在服务端检查；save 克隆手持物品，原物品不消耗；模板按单件保存，完整 NBT/组件保留。读取可指定历史版本，归档不破坏旧订单。
2. 内置持久化物品库：显式 SQLite 单节点模式或 MySQL 集群模式；事务保存不可变版本、当前目录和出站同步事件；并发保存顺序分配版本，SQL/网络失败不自动回退其他数据库。
3. 有界编码与解码、目录分页、完整背包容量预检、不向地上丢出溢出物品；保存/读取/给予/归档/策略变更审计。
4. 后端 WSS 主动连接：独立节点凭据、握手、心跳、退避重连、持久化 outbox、同 ID 去重、内容冲突保护、限长/背压、停用清理。
5. 物品元数据与归档/恢复同步后端；真实服务扩展原 Core 协议及管理查询。原始物品字节留在 Core 物品库，不经过 App/网页上传。
6. 公共聊天：TrChat 2.4.9 的最终公共发送事件适配；无 TrChat 时使用审核通过的 Bukkit 公共事件。只采集配置允许的公共频道，不采集私聊、Staff、验证码或代理回显。App 消息只显示一次，不触发 TrChat 再广播。
7. 玩家在线/身份查询、私密验证码投递、受控经济查询，以及需要持久执行身份的动作；不提供任意命令/SQL/任意物品字节执行入口。
8. 独立邮箱：按冻结快照从物品库解析并校验每个版本，调用创建/查询/撤回；转发带租约的持久事件，后端提交 ACK 后再确认邮箱事件；未知结果不换 ID 重发。
9. `/dc status/reconnect/reload/mail` 运维入口、Bukkit Services API、中文帮助和失败提示、清晰默认配置和四服示例。

## 跨服领取与外部同步边界

现有 YouerModSync 0.7-deuterium.2 仅找到二进制修补工程。已询问完整源码/维护任务，同时推进不依赖它的 Core 功能。不能把“等待数秒”“同步中集合为空”当作加载成功，也不能伪造 `MailPlayerDataBarrier.available=true`。

Core 提供明确的同步适配接口；生产集群必须接入可验证的加载、会话代次、发放屏障和保存回执。只有无其他同步插件的显式独立模式才能使用本机保存适配。没有真实同步能力时，物品库、消息、查询和安全状态提示仍工作，危险发放按能力拒绝。

Login 和 MEK 默认禁领；Amiya/Odyssey 也须满足实际兼容性及同步屏障。物品新增领取服务器范围必须验证节点配置/物品兼容条件；保存旧版本内容不因配置变更被改写。

## 验证与交付

- Java 单元/集成：SQLite 重启往返、同名并发版本、内容哈希、无修改原手持物品、权限、分页、归档/恢复、数量/大小/路径边界、背包不足、失去会话及异常发放保护。
- 后端＋Core：实际 Java WebSocket 客户端连接 Go 与真实 MariaDB，重连、重复/冲突、归档、节点认证、订单快照、邮箱事件 ACK 和跨节点重投。
- JAR 检查：入口与 `/dc` 注册、配置资源、Java 21 字节码、依赖隔离、无邮箱类、无 SDK/凭据。
- 在自己的隔离环境验证 Youer 加载与完整物品序列化；不启动、停止或覆盖其他任务的测试实例和生产服。真实玩家、MOD 客户端及生产同步屏障需分别记录证据，不能用 mock 声称实服通过。
- 交付 Core JAR、必要 API、后端增量、部署示例、命令说明与验收结果；不以“基础骨架完成”代替本轮插件开发。
