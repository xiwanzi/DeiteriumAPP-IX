# App 性能优化实施与等效验证

2026-09-11，用户已授权开始优化；延续“效果实现完全一样”的硬约束。基于 App 2.0.10 源码，维护分支 `xiwanzi/performance-equivalence-v210`。不包含线上发布、业务数据操作或游戏服务改动。

## 实施边界

保留原素材、布局公式、字号变化、玻璃 shader/参数、动画时长/曲线、支付时序/声音/振动、消息显示节奏及业务恢复顺序。基线见 `docs/reviews/artifacts/app-performance-v210/effect-baseline.json`。

本轮先保存原源码的本机固定场景画面，再实施可验证的内部优化：

1. 加购动画读取下沉、导航重组隔离、静态背景/裁切路径复用、通知偏好同批写入。
2. 商品、联系人、市场、订单/委托及账单派生数据按实际输入复用；有序历史使用等价插入/更新减少反复全量排序。
3. 图片授权解析缩小锁范围并保持批次、清理与账号隔离；AI 流式回复复用固定元数据，保持逐事件正文更新。
4. 请求身份耐久化迁离主线程，验证新增挂起点的并发、取消及先落盘后请求顺序；任何无法通过此验证的改动不保留。
5. 使用现有签名配置准备非 debuggable 的性能候选，保持库版本与资源，核验编译优化和打包 Profile 的实际状态。

联系人行虚拟化、后台刷新策略、上传流式文件寿命管理如不能证明当前交互/业务语义等效，则保留现状并记录原因，不用视觉降级代替优化。

## 验证

- 现有及针对性 JVM 测试：有序记录完整结果、快照失效、授权表继承/清理/并发、事件顺序和请求身份。
- Android 固定夹具：浅深色、大字号、首页展开/折叠、联系人、账单、卡片与玻璃；原版/优化版同设备同进度逐像素比较，排除系统状态栏等非应用窗口内容。
- 原生交互：加购/导航/开关、联系人更新、付款快/慢/失败/恢复、缓存、通知。
- 适当构建和 APK 核验；任何模拟器数据仅作为本机证据，不代替用户目标手机的帧轨迹和手感。
- 不因性能需求修改版本码或宣称上线；交付时列明实际完成、仍保留的热点和验证限制。
