## 已确认范围

只改 Go 后端及对应配置示例，保持现有 App、Web、启动器、Core 与 Gateway 的消息协议和业务接口。为未来的通知、人数等功能留出容量，但本轮不实现异常交易报警、团队人数和在线人数新功能，不预建通用消息平台。

## 请求容量分开管理

原实现所有处理函数共用 256 个槽，WebSocket/SSE 在连接结束前一直占槽。现在仅按已注册的操作路径分组，不相信客户端 Upgrade / Accept 头选择容量池。

| 分组 | 默认并发容量 | 范围 |
| --- | ---: | --- |
| 普通 HTTP | 256 | 其他业务请求，包括订单与登录 |
| 玩家实时连接 | 1024 | `GET /api/v1/chat/ws` |
| AI SSE | 64 | `POST /api/v1/ai/chat/stream`，包含重连订阅，不是生成数量 |
| Core 长连接 | 32 | `GET /bridge/v1/connect`，对应既有最多 32 节点约束 |
| 准入与运维 | 64 | Gateway check/poll、live/ready、管理员容量查询 |

前四个可调项目中的普通 HTTP、玩家实时、AI SSE 与准入容量分别由 `config.json` 的 `concurrency.httpRequests / realtimeConnections / aiStreams / controlRequests` 控制。省略或设为 0 使用上述默认值，负数或大于 16384 拒绝启动；修改需重启。Core 固定 32，避免引入重复节点配置。

满额继续使用既有 `503 SERVER_BUSY`，增加标准 `Retry-After: 1`。不增加自动重试写操作。普通 HTTP 饱和不会消耗准入/运维名额，但数据库、CPU 和网络仍共享；独立额度不是故障隔离保证。

1024 是长连接的准入上限，不是承载 1024 名活跃用户的验证结果。生产容量仍需结合查询等待、消息频率和连接数判断。

## 公共消息读取合并

只共享 WebSocket 的 `Messages(cursor, after=true, limit=50)` 读取：同一游标、同一 Hub 修订共用进行中的查询及最多 1 秒的成功结果。Hub 唤醒递增修订，使新消息无需等待 TTL；丢失唤醒仍由原有 5 秒轮询及 TTL 恢复。

缓存最多保存 128 个游标页，读到末页仍沿用原有补查与顺序逻辑；历史 HTTP 查询、私聊、会话和权限查询不缓存。每个连接仍先验证自己的会话。查询失败不缓存；等待者取消不会取消其他连接的共享 SQL，SQL 自身随服务关闭取消并有 5 秒期限。

慢连接/不同游标可能产生独立查询，Hub 的非聊天唤醒也会失效缓存。因此这是减少重复公共消息读取，不是消除所有每用户查询，也不增加跨实例缓存。

## 短时等待昂贵任务

- 密码校验保持 2 个槽及原 Argon2 参数。最多额外 32 个请求等待，每个最长 2 秒；取消释放等候位置，满额或超时仍返回原忙错误。登录限次、身份校验与会话创建未删减。
- AI 生成数量继续使用后台 `maxConcurrent`（当前生产为 4）；最多额外 16 个请求短时等待，最长 10 秒。100 ms 检查可用槽，不承诺严格 FIFO。仍使用既有 `pending / queued`、请求 ID、SSE meta/status/delta/error，客户端无需新的队列协议。
- AI 等待不占数据库连接或生成槽，但占 SSE 连接名额。生成开始前重新检查会话与持久请求状态。用户断开响应连接不自动重发生成；服务关闭终止等待，满额/超时使用既有失败收尾释放额度。收尾写入失败沿用持久 deadline 的未知结果恢复，不盲目重放外部请求。
- AI 等待使用原 deadline 的 30 秒余量；生成自身期限不超过持久 deadline。不改配额、收费、原请求去重或未知结果语义。

等待是吸收短突发，不保证所有集中请求都能成功；持续过载仍明确拒绝，不允许无限排队。

## 查看容量

新增后端运维接口 `GET /api/v1/admin/runtime/capacity`，要求已有 `platform.admin`，继续采用原 Cookie/Bearer 鉴权，无需增加客户端页面。

返回各请求分组的 active/limit/rejected、数据库 open/inUse/idle/waitCount/waitMilliseconds、公共消息 databaseReads/sharedReads，以及 AI generating/waiting/queueLimit/rejected。计数为进程内累计，重启归零；共享读取计数不等于实际节省的 SQL 总量。不返回账号、token、配置凭据或消息内容。

该接口只提供后续观察入口，不实现报警系统或后台管理页面。

## 部署与回退

候选无需数据库迁移，也不需要更新 App/Web/启动器/游戏插件。部署仍须单独安排新版 Go 切换；已有长连接会在重启时断开并按客户端既有逻辑恢复。

生产原配置省略 concurrency 即可采用新默认值。若添加了该节，回退旧 Go 前要从配置副本移除该节，因为旧版解析器拒绝未知字段。回退程序不恢复数据库、不重放未知交易。队列里的 AI 请求仍以数据库记录和期限恢复；不宣传跨进程无损排队。
