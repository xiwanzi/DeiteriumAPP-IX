# App 2.0.8 · 桌面图标与后台切换

2026-09-10。基于已发布 2.0.7，目标 App / Web 2.0.8，App versionCode 20800。

## 用户确认

- 默认使用已选定的白底黑色「弧线 D」。
- 同时内置用户确认的周年活动图标：相同 D，红色弧形活动栏，文案“911双子节”。
- 管理网页提供清晰的图标预览、当前启用状态和切换操作。
- 后续切换仅选择已经随 APK 安装的图标；不提供上传任意图片替换桌面主图标的入口。

## 实现边界

后端持久化一个全局目标图标和单调递增版本。只有 `platform.admin` 可修改，网页保留 Cookie / CSRF 校验；事务内再次检查权限，采用已有请求幂等机制和版本冲突检查，并记录管理审计。初始配置为 `default`。

客户端只接受 `default` / `anniversary_911` 两个内置标识，启动和回到前台拉取公共配置；前台周期补同步，已登录的聊天连接收到配置变更通知时立即补拉。事件只作提示，SQL 配置才是权威。断线、旧响应、未知标识、旧后端和请求失败均不导致图标丢失。

图标开关作用于本机已安装应用，不属于单个账号。实际 Activity 始终可用；默认 alias 保留旧 `.MainActivity` 的桌面组件名，活动 alias 指向同一真实 Activity。API 33+ 批量切换；更低版本先启用目标再停用另一入口。成功检查 PackageManager 状态后才保存已应用版本。关于页的 App 图标显示当前选择，登录 / 开屏版本徽标继续沿用现有规则。

管理页显示“配置已发布”，不把 HTTP 成功描述为所有手机已经刷新。旧版用户必须先升级到 2.0.8；离线设备恢复运行、联网后同步。系统桌面的缓存、位置保留和主题图标表现按实测记录区分。主题图标使用简洁的单色 D。

## 接口

- `GET /api/v1/app/launcher-icon`：公开的 `iconId`、`version`、`minAppVersionCode`、`updatedAt`，不包含管理员身份或私有数据。
- `GET /api/v1/admin/launcher-icon`：管理员读取当前配置及可选内置图标目录。
- `PUT /api/v1/admin/launcher-icon`：`clientRequestId`、`expectedVersion`、`iconId`。
- `app.launcher-icon.changed`：聊天 WebSocket 的单向配置变更提示；旧客户端忽略该未知事件。

新增独立配置表；保留现有业务数据、迁移和游戏插件。发布时先部署兼容旧客户端的后端，再发布网页和 APK。回退配置只切回 `default`，不删除旧资源或重置业务表。

## 验证

- 后端：普通用户拒绝、CSRF、非法图标、请求重放、版本冲突、并发保存、持久化、WebSocket 提示和旧客户端兼容。
- Android：两图资源、默认安装、20700 覆盖安装、切换往返、重开 / 离线保留、旧响应 / 未知图标、至少一个启动入口、通知打开目标及浅深色预览。
- 网页：桌面 / 手机、浅深色、选择与发布、加载 / 失败 / 冲突恢复、键盘操作、无横向溢出。
- 交付：App 版本 / 包名 / 同签名，Web 单测和构建，Go 竞态与集成测试。构建、交付和上线分别记录，不用候选版本号代表已上线。
