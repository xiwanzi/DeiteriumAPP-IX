# 全局过度绘制检查与处理边界

实施完成，最终真机结果、像素对照、产物与边界见[验收记录](../qa/app-global-overdraw-v210.md)。

2026-09-11，基于性能候选 `0492730`，分支 `xiwanzi/global-overdraw-v210`。用户报告所有页面 4 次以上过度绘制，并授权使用已连接 ADB 真机调试；延续原素材、渐变、动画和玻璃效果一致的要求。

## 已定位

手机实际安装 APK SHA-256 与上一轮候选完全相同：`78d5b52f3d821d516361fb4dce9f532c5bf8e5b083309c95bf91553d04dacdaf`。设备 API 37，1200×2670、520dpi、Skia Vulkan，原 `debug.hwui.overdraw=show`。有效的信息页画面显示空白背景也为全屏重度覆盖；随后一次外部批量截图全黑，已判定无效，不计为四页面证据。

`GlassAtmosphere` 为所有登录后页面连续执行底色和三次全屏渐变 `drawRect`；即使渐变在某处的 alpha 为零，仍有绘制命令覆盖整屏。外层另有同色根容器背景和窗口背景。`recordGlassBackdrop` 只记录并回放绘制指令，不等同于复用已合成的静态背景纹理。

玻璃自身的折射、模糊、遮罩与高光局部绘制保留。不能因为 Debug GPU Overdraw 显示红色，就把绘制次数等同于实际 GPU 时间；当前 gfxinfo 是历史累计样本，收益需要独立同条件测量。

## 处理方向与验证门槛

1. 去除被页面完全覆盖的根容器底色，保留窗口底色、登录/恢复兜底和所有渐变参数。
2. 静态氛围背景在尺寸、配色或密度变化时准备一次；后续屏幕绘制复用合成结果，页面、滚动及动态内容仍逐帧正常绘制。
3. 玻璃采样继续读取原始背景绘制源及当前页面内容，避免多一次纹理采样改变像素；不降低图片、模糊、折射质量，不冻结动态前景。
4. 对照原多次绘制、整段着色合并、普通缓存及分离显示/采样源四种实现。API 35 模拟器预检发现：着色合并有 1–2 级色差；普通缓存背景本身一致，但玻璃有 1 级色差；分离源在浅深色背景及玻璃场景均零像素差异。模拟器不替代 API 37 真机。
5. 真机固定画面逐像素对照、实际四页面过度绘制、主题/尺寸变化、滚动前景与玻璃联动、关闭调试着色后的帧时序分别记录。必要时保留一个屏幕大小的 GPU 纹理，记录其内存成本，避免以隐藏计数代替减少重复工作。

测试组件使用独立渲染夹具；不改登录身份、服务端数据或业务配置。安装保留 App 数据，不清除应用数据。调试着色临时切换后恢复用户原值；首次测试安装被手机系统拒绝，用户已要求重发并允许安装。未授权线上发布。
