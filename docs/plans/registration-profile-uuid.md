# 注册正版 UUID 留存与未验证账号改名

2026-10-14，用户要求为现有账号保存正版 UUID，并支持新名字解析到相同 UUID 后沿用原账号登录。

## 已确认边界

- 注册时的公开正版资料只证明名字与 UUID 的对应关系，不证明用户拥有游戏账号。`profile_uuid` 保存该对应关系，原 `server_uuid` 和 `game_verified` 继续代表进服验证结果；资产、白名单和游戏权限不因公开查询而绑定。
- 获取注册验证码时保留完整 UUID，随邮箱验证记录写入注册账号；十分钟查询缓存保留 UUID，最终提交无需额外联网。上线前签发的旧验证码缺 UUID 时补查。
- 新游戏名登录：查询官方 UUID，定位原账号，原密码成功后事务更新名称和登录别名，保留账号、昵称、密码、邮箱、会话及资产。错密码、UUID 冲突、迟到查询和已删除账号不更新。
- 未验证账号的改名不发布游戏资产身份映射；之后进服绑定必须匹配已保存的正版 UUID。已验证账号沿用既有名称事件同步。
- 现有未删除账号优先复制已验证 UUID；其余逐个查询当前名字。旧名失效时查历史证据，不按相似名字猜测。不恢复已删除账号，不启动游戏服务器。
- 邮箱登录继续走原验证路径，不加入全量扫描或固定查询任务。本轮不调整密码强度和登录限流。

## 验收

覆盖注册缓存和验证码留存、未验证账号新名登录、错密码不改名、重复 UUID 注册、邮箱登录、并发/迟到证明、改密竞争、游戏 UUID 不匹配、管理员改名和永久注销；使用隔离 MariaDB。上线前备份、核对既有迁移及身份数据，回填只补 UUID，不批量更换游戏名；回退程序不回滚用户业务记录。
