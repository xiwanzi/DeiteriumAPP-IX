# 跨店合并付款与优惠券页恢复

2026-10-08 用户要求：优惠券详情卡恢复截图中的原样，其他优惠展示保持；购物袋可同时结算多店商品，一次确认付款，按店生成独立订单、分别发送游戏邮件，历史订单独立展示。基线 App 2.0.20 / Web 2.0.29，源码主线 `14bc0a3`。

## 已确认边界与实施

- 优惠券页恢复正文色金额/门槛和原蓝色提示，商城商品优惠仍使用粉色。
- 每家店沿用一个订单、一份快照、独立托管资金、邮件、领取及退款。一次用户授权创建整组订单，服务端事务原子校验并占用全部库存/券，任一不满足则整体不创建。
- 优惠按拆分后的各店订单计算，每单最多一张券，同一张券在整次付款中最多使用一次。共享券选择总优惠最大的合法分配，门槛不跨店凑单，沿用单店优惠算法。付款重新核验已确认的优惠，不临时替换券或金额。
- 复用现有 Core 独立托管接口，在同一个可恢复的付款操作中先完成各店资金预留，再分别发邮件。某店预留明确失败时，尚未预留的订单取消，已有预留自动原路退回；结果未知时继续核对原操作，不重扣、不发邮件。
- 资金全部确认后，单店投递失败只影响该店订单，沿用后台重试和未领取退款；其余店正常投递。各订单仍有独立资金凭据与退款上限。
- 重启/断网按原 clientRequestId 与 operationId 恢复整组订单；完成后购物袋只扣除已付款数量，历史订单显示每店真实金额。旧单店、玩家市场、委托不改变协议行为；游戏插件不更换。

## 验收

隔离数据库验证两店订单/邮件/资金拆分、单次确认与总额、跨店券不重用及最优分配、报价过期/改价、库存不足整体回滚、重复并发、扣款结果未知恢复、后店预留失败补偿、补偿未知、投递失败隔离、各店退款/返券、后台权限隔离。App 验证合计与店铺明细、一次付款反馈、重开恢复与独立历史，优惠券页浅深色。运行相应 Go/Android/Web 测试和构建，发布前核对原有业务数据及同签名更新。
