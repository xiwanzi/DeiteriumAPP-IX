# 工作人员主动建单

2026-10-04 用户确认：工作台增加新建工单，可以主动向任意有效邮箱发出首封邮件；首封邮件复用人工回复模板，顶部显示工单编号；不发送“工单已收到”自动回执。

- 仅 support.manage / platform.admin。每单一个收件邮箱、主题、类型、正文；默认分配创建人、普通优先级、WAITING_CUSTOMER。可联系未注册用户，不创建 App 账号；已注册邮箱仅作资料关联。
- 在同一幂等事务中生成现有日期+四位编号、工单、OUTBOUND 首条消息、ENTERPRISE/TICKET_REPLY 发信任务、邮件线程关联及审计。source=ADMIN，沿用既有 VARCHAR 字段，无迁移。
- 首封无虚构的 In-Reply-To；玩家尚未回复时仍可继续发信，后续邮件引用已有邮件。玩家回复按现有线程/同邮箱编号接续，原单重新 OPEN；无新建回执。
- 禁止以系统自有发信/收件邮箱为收件人；输入无效、未授权、通道未启用时整笔回滚。不接受客户端提供的玩家 ID 或邮箱发件身份。
- 确认按钮“创建并发送”，说明不发自动回执；失败保留表单；结果未知锁定原请求内容并使用同一请求 ID 重试。成功打开新单。邮件显示队列/投递结果，不把入队称为已送达。
- 验证权限、非法地址、通道关闭、事务回滚、并发/重复提交、首次正文编号、没有回执、补发与收到回复后的归并及越权隔离。真实用户邮件不作为自动验收数据。

## 超级管理员修改其他账号的游戏 ID

同轮追加需求已确认：编辑游戏 ID／游戏名，不是昵称或内部 userId。

- 单独 POST /admin/accounts/{userId}/game-id，platform.admin 专用；不能通过该入口改当前管理员自身、已注销账号或保留系统名。输入沿现有 1–32 位英文字母/数字/下划线格式。
- 未验证账号可修正填写的游戏名；已验证账号非大小写改名须由现有 Core 名称解析确认仍属原 UUID，绝不迁移到其他游戏身份。内部 userId/playerRef/UUID、QQ、邮箱、昵称、权限、余额、订单和白名单不变；本入口不修改游戏服务器用户名。
- 在原账号版本和事务锁下更新 game_id、新登录别名、撤销旧游戏名别名（保留同名 QQ 别名）、失效旧游戏验证码、撤销目标账号旧会话并记审计。用户重新登录即可取得新信息。重名、版本冲突和重复提交均有明确处理。
- 改名与游戏验证码签发/消费并发时检查当前账号游戏名，防止旧验证码把新名称覆盖回去。
