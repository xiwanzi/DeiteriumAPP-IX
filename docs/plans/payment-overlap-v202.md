# 2.0.2 支付请求与模拟识别并行

2026-09-08，用户明确要求实现并直接发布 2.0.2。

- 用户按下原确认付款按钮后进入支付界面，立即执行原 onCommit 请求，同时保留 1–3 秒模拟识别。
- 删除额外的 470ms/100ms 提交前等待。识别与后端结果分别完成，只有识别结束且真实成功才显示确认勾；请求较慢继续等待，失败显示失败，未知结果沿用原恢复流程。
- 提前收到的结果立即保存在可恢复界面状态中，避免在模拟识别期间重建界面重发已完成请求。已确认的恢复结果不被晚到失败覆盖，也不跳过剩余识别。
- 转账确认时固定原请求 ID 和已验证收款人引用，重建/重试使用同一键；只有键、收款人、金额和备注一致才复用原待确认请求。商城、市场和委托继续沿用各自已保存的幂等键。
- 不修改服务端资金、鉴权或结算接口；APK 2.0.2 (20200) 沿用原包名和签名。

验收：快响应不提前出勾、慢响应继续等待、失败不显示成功、重组/状态恢复不重复提交、恢复成功不被失败覆盖；构建、单元测试、Lint、签名及公网更新验证。测试用独立 androidTest 回调，不发起真实付款。
