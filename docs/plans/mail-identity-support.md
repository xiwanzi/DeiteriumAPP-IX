# 邮件、账号验证与工单改造

日期：2026-10-03。基于 `05cc6dd`；工作分支 `xiwanzi/mail-identity-support`。本文记录本轮实现边界，不代表已经部署。

## 已确认需求

- 原 SMTP 栏目升级为邮件系统，SMTP 成为发送通道设置子项。
- 阿里云 DM 承担注册验证码、已有白名单审批结果和其他自动通知；企业邮箱承担官方手动邮件及工单回复。
- 邮箱验证码创建真实账号；游戏验证码独立为后续验证。账号登录后，未验证时进入验证页，不能使用社区及 App 常规业务。
- 本次迁移前的所有既有账号默认已验证。账号、订单、委托、注销记录及白名单状态保留；身份验证不能恢复或授予白名单。
- 原管理员保留完整权限并显示为超级管理员；新增管理员仅使用工单管理。后台接口必须实施权限校验。
- Web 与 Android 保持各自现有视觉、主题、连续跳转和动效偏好。

## 实现假设与权限

用户已选方案二：注册填写游戏 ID、任意邮箱、邮箱验证码及密码；随后补 QQ、验证游戏验证码。邮箱与游戏 ID 可登录，昵称独立支持中文修改。未验证账号可以通过邮件求助；不提供站内工单对话。游戏 ID 在注册时作为登录别名预留，服务器 UUID 仅在游戏验证时绑定；不能用注册时自填的游戏 ID 证明身份。服务器 UUID 仍仅由 Core 解析，绑定冲突不合并身份或资产。玩家引用创建后固定不变。

超级管理员沿用 `platform.admin` 权限以兼容现有管理模块；新增 `support.manage` 仅授权工单工作台，不能进入邮件配置、账号管理、模型、白名单、商品或财务裁决。工单管理员查阅的上下文限定于工单相关用户；直接来信的邮箱关联不充当登录或资产操作的身份凭证；内部备注不向申请人返回，不外发邮件。

## 已确认邮箱

- Help 内部发信：`go@deuteriumix.com`。
- 客服收件及人工回复：`support@deuteriumix.com`。
- DM 自动发信：`noreply@notify.deuteriumix.com`，发信域名 `notify.deuteriumix.com`；地域为华东 1（杭州），SMTP `smtpdm.aliyun.com:465`；SMTP/IMAP 授权码在后台配置。
- 默认地址可在对应通道表单中调整；没有凭据和明确启用前不连接真实邮箱。

## 数据流与失败处理

1. 注册邮箱获取一次性验证码：按 IP、邮箱限次及冷却；验证码散列存储，发信内容加密入队；过期或替换后取消旧邮件。注册消费验证码与创建账号在同一事务中完成。
2. 邮箱账号登录得到真实会话，`gameVerified=false`；服务端统一限制业务访问，保留会话查询、退出、游戏验证以及未来 Help 表单的邮件提交接口。
3. 游戏验证码绑定当前会话账号与 Core 解析身份；成功后刷新会话数据并进入业务页面。并发重复绑定、验证码重放、已绑定 UUID/QQ/游戏名拒绝。
4. 旧自动通知复用既有队列和模板，经 DM 通道发送；企业邮箱独立配置、独立投递。邮件记录区分已入队、邮件服务器已接收和失败，不能将 SMTP 接收表述为收件箱已送达。
5. 用户最新明确要求工单完全由邮件驱动：玩家可直接给客服邮箱发信；未来 Help 表单必须登录，内部系统邮箱发送至客服邮箱，Reply-To 为当前玩家邮箱。Help 提交仅产生转交邮件，客服收到后才建单。
6. 客服收件箱通过 IMAP/TLS 只读同步；按来源、UIDVALIDITY/UID、Message-ID 去重。工单编号固定 UTC+8 的 YYYYMMDD 加四位随机数字；每日序号空间加锁并从未使用值中随机取号。建单事务原子加入 DM 模板回执。
7. 后续邮件先按 In-Reply-To/References 关联并校验回复邮箱；缺少引用时仅对相同玩家邮箱识别主题中的明确工单编号。系统转交邮件须匹配一次性服务端证明和绑定玩家邮箱，不能仅信任伪造的 From/Reply-To。
8. 后台提供状态与类型颜色标签、队列/搜索、指派、优先级、邮件回复、内部备注、快捷回复、附件读取和投递状态。回复与邮件入队同事务；内部备注绝不外发。发送与等待回复/继续处理/解决状态可以一次提交。
9. 自动回复、退信和系统回环邮件不建单；无法解析或超限来信保留在原邮箱并显示人工查看提示。默认接收配置启用后的来信，可明确选择首次导入历史邮件。

## 迁移与回退

只增加新迁移；现有账号回填已验证，新增邮箱账号显式未验证。游戏 UUID 允许为空，不能用伪造 UUID 代替绑定。旧 SMTP 配置与授权码保留为历史通道，DM 未配置时明确展示待配置状态，不偷偷将验证码发往旧通道。

发布前备份数据库、邮件加密密钥及现有配置；先部署兼容迁移和后端，再发布 Web/App。回退二进制前必须评估新增未验证账号：旧服务无法正确执行验证门禁，不能直接回退旧版本开放业务；优先前向修复或临时关闭注册。禁止删除新账号或业务数据作为回退。

## 验证

- 隔离数据库验证迁移、旧账号回填、旧权限保留和未验证业务拒绝。
- 验证码过期/错误限次/并发消费、跨账号绑定、邮箱重复、服务器身份冲突。
- 普通用户无后台工单访问；Help 只发送邮件，不直接建单；工单管理员无其他后台权限；内部备注及凭据隔离。
- 邮件通道路由、幂等入队、失败恢复、旧通知模板与队列兼容。
- Web 构建与浏览器浅深色、移动端、注册到验证跳转、邮件工单和回执模板；Android 模块构建和现有测试。真机、真实 SMTP 和生产部署单独报告实测状态。

## 设计依据

- [Zendesk Agent Workspace](https://support.zendesk.com/hc/en-us/articles/4408821905434-Agent-Workspace-for-messaging)：参考队列、对话编辑器和内部备注。
- [Zendesk 快捷回复](https://support.zendesk.com/hc/en-us/articles/4408887656602-Using-macros-to-update-tickets)：参考复用答复，发送前仍由操作人确认内容。
