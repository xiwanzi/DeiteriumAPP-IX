# 游戏 ID 登录快速路径

2026-10-25：用户同意实施 10-16 讨论的本地认证优先方案。既有正式基线为 Go bec12a61ada8、App 2.0.29、Web 2.0.41；实施/验收/上线分别记录。

## 已确认边界

- 本地已知游戏别名＋该平台账号正确密码，先签发原平台账号会话，不等待官方接口。名字与 UUID 更新由成功登录后的后台任务完成；平台 ID、UUID、资产、角色和已验证状态不转移。
- 本地找不到名字，或已知游戏别名密码不匹配（包括原映射账号被限次），才查询官方名字→UUID，定位账号并验证该账号密码。邮箱/QQ仍只按其本地绑定查找。一次请求不重复计算同一账号同一密码哈希，也不重复占用其失败预算。
- 这是从「每次使用官方即时名字归属」改为「本地平台登录别名、后台同步」的有意语义调整：未观察到改名/名字复用前，旧别名可暂时认证原账号；两个账号密码恰好相同时不能仅凭本地输入证明玩家期望的官方当前持有人。不得声称实现实时官方归属等价。已发现的新归属必须更新/失效旧映射，已有会话始终属于原平台主体。
- 签发会话事务内复查登录别名仍指向已验证密码的同一平台账号，保留当前密码、状态、注销/解除登记、并发改密和权限检查。公开 UUID 不授予游戏权限，未验证账号后台改名后仍未验证。
- 后台按稳定 UUID 查询，使用现有官方请求池与迟到证明保护；单工作线程、有限队列/冷却记录、同 UUID 合并，成功十分钟内不重复，失败一分钟后由后续登录重试。进服事件同步保持。关闭服务取消任务，不使用请求结束即取消的登录 context，也不为每次登录创建无界 goroutine。
- 官网账号按钮立即打开已有登录/账号界面，不串行等待会话 GET；页面恢复仍在后台验证。聚焦/可见性刷新适度合并，不缓存权限判断或放宽服务端认证。中英文入口一并验证。

## 验收

阻塞/失败官方服务下已知正确密码仍迅速返回；后台最终改名且既有会话主体不变。新名首次登录、名字复用、错误密码、稳定 userId 限次、并发改密、别名在 KDF 期间变化、未验证身份和退出关闭均回归。慢外部接口与快速路径对照明确区分本机模拟和真实公网测量。

无数据库迁移；不减少密码安全参数，不更换 App 或游戏程序。上线只在候选构件、数据保护与回退方案完整后进行。
