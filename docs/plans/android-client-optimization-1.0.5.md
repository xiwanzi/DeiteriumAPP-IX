# Android 客户端兼容优化计划（1.0.5）

## 目标

以当前手机安装的 `1.0.4` AI-SSE 非 Canary 版本为行为和兼容基线，修复已确认的转账、聊天与生命周期问题，并降低启动请求、主线程解析、数据库写入和高刷新率带来的开销。

本次交付应当能够使用当前后端直接运行和覆盖安装，不要求同步发布后端或 Minecraft 插件。

## 不做什么

- 不新增、删除或修改 HTTP 与 WebSocket 路径。
- 不修改请求字段、响应字段、错误码或鉴权方式。
- 不修改后端、Minecraft 插件、数据库表或协议文档。
- 不改变 Debug 环境既有的 HTTP/WS 联调配置。
- 不引入新的 Android 框架、依赖注入方案或持久化库。
- 不进行与本轮问题无关的 UI 改版。

## 涉及端

- Android：实现全部优化。
- 后端：不修改，继续使用现有 `clientRequestId` 幂等、聊天 WebSocket 和查询接口。
- Minecraft 插件：不修改。
- 文档：新增本计划，记录兼容边界和验收方式。

## 数据流与实现范围

### 钱包与转账

1. 用户确认收款人、金额和备注。
2. Android 在提交前持久化本次转账意图及 `clientRequestId`。
3. 网络失败或结果未知后，相同转账意图重试时复用同一 `clientRequestId`。
4. 后端依照既有幂等规则返回同一转账结果，不重复扣款。
5. 明确成功或明确业务失败后，Android 清除本地待确认记录。

收款人搜索增加取消和结果代次校验；输入发生变化时立即清除已确认收款人，避免旧结果覆盖新输入。

### 聊天

1. WebSocket 文本先在后台线程完整解析为客户端内部事件。
2. 无效或不完整事件被安全忽略，不影响连接和进程。
3. 解析完成后仅在主线程提交 Compose 状态。
4. 最近消息、在线状态、玩家目录和关注列表增加请求合并及短期新鲜度控制。
5. 聊天页前台停留期间保留 15 秒静默补齐，但与其他同步入口去重。
6. 实时消息按短时间窗口批量写入 SQLite；每账号仅保留最近 5000 条。
7. 历史搜索增加防抖，避免每个输入字符立即扫描数据库。

### 生命周期与界面性能

- Activity/Composition 销毁时终止 ChatRepository 的 WebSocket、重连任务和内部协程。
- 普通 Retrofit 请求正确传播协程取消。
- 不再强制设备使用最高刷新率，由系统选择显示模式。
- AI 流式回复不再随每个内容增量重复滚动，并降低状态发布频率。

## 关键失败场景

- 转账已在服务端成功，但客户端超时或断网。
- 收款人搜索过程中继续修改输入或连续发起搜索。
- WebSocket 收到缺字段、错误类型或无法反序列化的数据。
- Activity 重建时旧连接仍在重连或回调。
- 登录、恢复前台和 WebSocket 建连同时触发相同同步。
- 聊天短时间大量到达、本地历史长期增长。
- AI 回复较长且持续流式输出。

## 验收标准

- Android 变更不包含 `backend-api/`、`minecraft-plugin/` 或 API 契约文件。
- 包名保持 `com.deuterium.app`，签名证书与手机现有 Debug 版一致。
- `versionCode` 提升，能够通过 `adb install -r` 覆盖安装。
- 相同转账意图在超时后重试复用同一 `clientRequestId`。
- 修改收款人输入后，旧收款人不可继续提交；过期搜索结果不会覆盖当前结果。
- WebSocket 异常数据不会抛出未捕获异常。
- Activity 销毁后旧 WebSocket 和内部协程被终止。
- 启动、恢复和 WebSocket 建连的重复同步被合并。
- 聊天历史有上限、搜索有防抖、实时写入按批次执行。
- 单元测试、Debug 构建和 Android lint 通过。

## 已确认假设

- 当前后端已经按既有契约对相同 `clientRequestId` 和相同转账内容返回同一结果。
- 后台 WebSocket 继续用于关注玩家、提及和钱包通知，本轮不改变该产品行为。
- Debug 明文 HTTP/WS 是用户明确接受的联调约束，本轮不修改。
