# 体验版 08：顶部安全区域、统一反馈与启动过渡

## 本轮范围

依据用户于 2026-09-08 的最新要求，继续在 `android-app/ui-lab` 优化原生 Android 体验并交付可覆盖安装的 08 APK。关联任务“评估网页版接口缺口”用于理解共用契约及网页工作边界，本轮不实现网页或业务后端，不混入该任务的封禁/会话等草案。

本轮包括二级页顶部模糊遮挡、页面/浮层过渡一致性、支付图标与提示音、两组独立材质默认值、冷启动载入。保留已有资金状态、订单数据及幂等规则，不将模拟面容确认变成真实人脸识别。

## 已确认变化

- 二级页初始内容必须位于顶部渐变的安全区域之外，历史账单“全部 / 收入 / 支出”等首行控件进入时清晰；滚动到顶栏下方时仍有连续模糊，不能恢复硬切割。
- 支付成功图标移除独立白色圆底，支付容器不重复叠加额外背景遮罩。检查转账表单到支付结果的切换，统一页面、卡片与底部弹层的进入/退出节奏。
- 参考用户提供的《一小时 Apple Pay 支付声 叮一声》，短链解析为 `https://www.bilibili.com/video/BV1RK4y1r7Yz/`；先读取实际画面、声音及时间线，再调整面容扫描到确认动画，不能仅凭名称声称复刻。仅取所需的短提示音，不下载或打包一小时视频。
- 浮层玻璃默认：模糊 36dp、表面不透明度 65%、折射 24、高光 30%；底栏默认：4dp、12%、24、30%。按当前滑条“不透明度”口径实现用户所称透明度。两组数值、开关、修改和还原分别保存，顶部渐变保持独立。
- 首次迁移到两组参数时采用本轮指定默认值；保留现有两类玻璃开关和其他用户偏好、业务记录。迁移后用户调整独立持久化，不能下次启动又恢复默认。
- 将裸露的“正在恢复本机记录…”替换为品牌启动过渡。真实数据在后台读取，首页就绪后平滑显露；不伪造联网同步进度，不添加长时间无意义等待。旋转屏幕和应用内返回不重新播放完整冷启动动画，减少动态效果时缩短反馈。

## 实施与边界

Android 端调整顶部渐变布局边界、材质状态/持久化与调节面板、共享浮层/支付反馈、启动主题与载入门控。业务模型沿用当前保存与恢复流程。支付成功提示只在真实的本机提交成功后播放一次，失败不得播成功音或显示成功勾。

文档只同步用户指定的两组材质默认值及客户端实现状态；保留已补的 OSS 直传、可见性和远程外观契约。本轮未提供生产服务地址，不自动宣称已接入远程参数、OSS 上传或真实支付。

## 验收

- 08 与 07 同包名同签名，覆盖安装保留钱包/订单/资料；两组默认值及分别修改/还原/重启保存正确。
- 历史账单、订单、外观、通知、更新等二级页初始首行清晰；滚动渐变连续；聊天标题和键盘边界正确。
- 转账、商城/市场、委托复用同一支付动画，成功无独立圆底/白色叠层；失败、重复点击、动效关闭和退出不重复提交或播放成功反馈。
- 冷启动有品牌载入及顺滑显露，进程恢复不泄漏旧账号内容；浅深色均无白屏闪烁，已有记录在首页可操作前恢复。
- 检查参考短片与最终录屏；构建、必要单测、Lint、版本/签名/权限/校验值验证。模拟器记录视觉与音频调用，真机音量/触感和 GPU 表现仍由手机体验确认。


## 追加确认与素材核对

- 用户要求优先寻找真实 SDK/官方原始素材。已核对 Apple Pay 官方资源/设计模板、公开 Web SDK，以及下载的 Apple Pay、LocalAuthentication 官方示例包，未找到可独立用于 Android 的完整确认动画与提示音。未把第三方屏保或自行转换的数据标为官方 SDK。
- 采用用户参考视频的实际帧序列与短提示音作为退路：扫描和翻转光环采用参考视频的透明帧序列以保留柔和渐变，最终圆环/勾号拟合为原生 Canvas 路径；不打包参考背景、白色圆底或一小时视频。
- 用户进一步明确：版本徽标只用于登录页；系统开屏、载入过渡、注册及关于页使用 App 实际 launcher icon，不再使用版本徽标。资源包中的版本徽标更新仍可在登录页显示。
