# 网页官方管理体验优化

基线：`251ac68`，线上 Web / Go 2.0.4，App 2.0.5。本轮在 `feat/desktop-admin-experience` 独立工作区实现。

## 已确认范围

PC 管理导航与商品列表、商品编辑手机预览、图片实际裁切区域和像素尺寸、游戏内邮件标题正文配置、公共聊天等玩家头像、网页商品购买体验。沿用现有 React / CSS 和业务接口。

## 实施边界

- 管理工作区使用持久侧边导航，商品列表提供关键词、状态、分类筛选和分页。窄屏折叠导航、表格局部横向滚动。
- 商品编辑左右分栏，表单与手机预览联动，保留草稿/发布、版本冲突、同请求重试和未保存保护。
- 预览对照当前 Android `Storefront.kt` / `ProductMedia.kt`：推荐海报 308 × 405 dp、双列图 `(屏宽 − 52) / 2 × 170 dp`、详情 `(屏宽 − 40) × 260 dp`、购物袋 80 × 100 dp，均居中 cover。预览为布局模拟；dp 与原图 px 分别标示，字号/系统缩放可能造成设备差异。只预览裁切，不改变上传原图或声称保存焦点位置。
- 商品增加可选 `mailTitle`、`mailBody` 纯文本字段；分别最多 80 字/240 UTF-8 字节、1000 字/3000 UTF-8 字节。空白沿用原默认内容。保存草稿后须发布才影响新订单。
- 单种商品订单使用该商品已发布文案；多种商品合并为一封邮件，默认订单标题、正文按商品 ID 稳定顺序分节保留各商品文案和数量。合并正文超过现有 Core 4096 字节限制时，报价阶段提示分开购买；不截断，不增加邮件数量，不改变附件和资金流程。
- 邮件内容在订单创建时进入既有持久投递计划，之后修改商品不影响已成交/重试订单。沿用权限、幂等键及冻结物品快照，不改数据库结构、Core 或独立 Mail 协议。
- 聊天保留服务器返回的头像，图片失败有姓名占位，后续新头像 URL 可恢复。购买仍由服务端报价和资金状态决定结果。

## 验证与交付

Web 单测/构建、Go 文案校验与快照集成测试；Playwright 隔离夹具检查 PC、窄屏、浅深色、裁切、输入联动、保存发布、头像、报价及未知结果恢复。夹具不连接生产账号或真实资金。最终记录实现、测试证据与部署状态；本计划编写于开发阶段，最终状态见 [网页 2.0.5 部署记录](../deployment/web-2.0.5-live.md)。
