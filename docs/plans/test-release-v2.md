2026-09-08。用户授权修复启动徽标、去除 App/Web 演示数据及模拟登录、App 2.0.0，完成三端同步和实际部署，以 APP 优先。真实目标为 Linux `https://47.103.99.34`，Minecraft 使用现有 Windows 四服；域名备案中。

本分支 `codex/test-release-v2` 从后端 Foundation `8db1109` 建立，补客户端所需业务增量。另一正在运行的后端任务继续维护 `.worktrees/backend-rewrite` 的 Core Java、Go 远程命令与经济/验证码连接。此分支不覆盖其工作区；通过明确提交和三方合并集成。新业务采用 `*_v2.go` 与编号 `010` 及后的迁移，避免修改已交付 `001_foundation.sql`。

## 已确认边界

- 保留 App 当前 UI；清除示例和旧本机资产，真实读写统一走 API。没有后端结果不能显示发送、付款、领取或退款成功。
- 身份沿稳定 `userId` 和插件权威 UUID；不能按名字生成 UUID。旧账号迁移只含账号，不声称迁移余额或聊天历史。
- 资料/私聊/通知/订单权限由服务端校验。管理员仅向用户指定的 `xiwanzi` 稳定身份显式授予。普通用户不能通过客户端参数得到管理权限。
- 私聊消息只由会话当事人读取；引用/转发需源消息读取权限，转发记录为原消息快照，公开聊天不能泄露私聊/管理内容。聊天幂等依身份和原 clientMessageId，重连不能重复写入。
- 正式交易由 XConomy/Vault 权威执行，余额不足/离线/未知结果必须保留准确状态。平台冻结/结算/退款涉及的持久命令使用同一 operationId，不能通过新 ID 重试或本地改余额。
- 更新仅发布已验证 APK/资源的元数据；不运行资源包代码，不将调试文件或私有配置放入公网目录。
- 授权测试身份：xiwanzi 转出、luoyinwuchen1 收款；若 xiwanzi 余额不足，可通过游戏控制台补款。测试金额和实际结果写入部署记录。
- 用户随后明确资金专户：继续使用 XConomy，`DIMA` 为官方商城收款账户，`DaoYu` 为冻结资金账户。预付由付款人转入 DaoYu，市场/委托结算到固定玩家；官方商城领取后结算到 DIMA，退款从 DaoYu 原路返回。两个账户是 Core 管理的系统经济身份，不伪造 QQ/密码生成普通 App 玩家；先检查名称冲突，再通过服务端受控初始化并保存权威 UUID。禁止普通用户把它们作为转出账户，担保账本合计须与真实专户余额对账。

## 实施顺序

1. 在不干扰 Core/RPC 的前提下补资料、私聊/引用/转发、公告、通知、设置/更新接口及权限测试；将端点和字段与已有 v2 OpenAPI 对齐。
2. 接收并合入另一任务的 Core、经济和验证码实现，对齐 App/Web 的真实登录和钱包动作，做 SQL 集成和桥接故障测试。
3. 核对商城、市场和委托的列表、详情、发布及交易状态；需要资金的动作只有在可靠经济/邮箱能力就绪时执行，不能临时本地模拟成功。
4. 构建并部署统一产物；旧账号只读导出/预检/导入；Nginx 和后端系统服务回滚保留旧版、凭据和数据库备份。
5. 用用户确认的游戏身份验证跨端消息、转账、受控发放，并更新能力矩阵，区分本机通过、Linux通过、实服通过和客户端人工体验。

## 验证与失败情形

检查会话撤销、跨用户读取/写入、权限拒绝、重复请求、分页、断线重连、服务重启与原操作恢复。公开数据从空库开始，不自动播种。对资金与邮箱故障应测试冲突和 UNKNOWN，不把不可达当作没有执行。客户端 UI 的浅深色和启动过渡由 Android 子任务独立验收；纯静态网页与 API 同源，浏览器 Cookie、CSRF 与 WSS 在 IP HTTPS 下验证。
