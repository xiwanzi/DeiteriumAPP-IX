# 通行申请、白名单管理与 Velocity 重连

2026-09-12。本轮用户明确授权实现并上线：独立通行申请站、现有后台的申请审批/手动添加/移除白名单、Velocity 全群准入，以及重新登录返回上次游玩子服。申请站暂用独立 IP 端口，将来再切独立域名，不依附现有网页版子域名。

## 基线与范围

- 从 `origin/main` 的 `73d3c54` 建立独立工作区；线上基线是 App 2.0.13、Web 2.0.15 和对应 Go，保留账号注销、启动器及原业务数据。
- 前端沿用用户确认的终末地式界面、IX 版本徽章及最后提供的 DSA 方块发射图。公开申请不要求先注册 App。
- 用户补充明确本轮只做独立网页，不修改 Android 登录页或发布新版 APK。
- Go 保存申请、当前白名单和不可变操作记录；管理员操作沿用现有身份、`platform.admin` 权限、CSRF、幂等及版本冲突机制。
- 新增独立 `velocity-gateway` 模块，不把 Bukkit/Youer Core 搬到代理，不改资金、背包或游戏存档流程。

## 身份与审批

申请包含正版 Java 玩家名、QQ、可选玩法与备注、公约版本及主动同意。后端解析正版 UUID；玩家名可查询不代表提交者拥有账号。审批人必须确认 QQ 群成员身份及申请者对所填账号的使用权。第一版不伪造 QQ 机器人核验。

白名单以 UUID 为主键，游戏名为展示信息。待审申请和当前通行资格分离，移除资格保留申请和审计。手动添加通过同一正版身份解析与审计流程，不要求创建 App 账号。公开查询使用随机凭证，不凭 QQ/玩家名公开申请资料。

## 准入与重连

Velocity 在正版认证后、进入任何子服前异步调用有独立节点凭据的 Go 准入接口。超时/网络故障拒绝本次新连接并给出重试提示，不默认放行。

只有通过准入才选择上次成功游玩的子服。用户本轮补充明确默认入口改为 **Amiya**：没有记录时先进入 Amiya；上次子服不可用时优先回 Amiya，必要时由配置的备用服承接。临时回退不覆盖原游玩记录。手动切换成功后更新记录；本地原子持久化使代理重启仍能保留，旧连接的迟到回调不得覆盖新会话。现有 Velocity `try` 的首项同步改为 `amiya`。

移除白名单后新连接立即拒绝。管理员可选择同时踢出在线玩家；通过代理主动轮询和确认回执完成，后台明确区分已撤销与在线断开执行结果。代理不开放公网管理端口，不接收任意命令。

## 切换、验证与回退

先只读核对线上代理路由、插件和已入服玩家，以实际游戏身份和既有名单准备老玩家迁移，保留封禁规则。启用准入前验证导入数量、名单、节点凭据和非白名单拒绝，不清空原名单或玩家数据。

新增数据库迁移，发布前备份；后端、管理网站、独立申请站和代理 JAR 分别留存原版本。代理重启尽量选空服窗口；必须重启时保留数据并验证所有原节点恢复。原应用和其他服务不得被回退到旧源码。

验证覆盖公开申请防刷/格式/重试、未知结果恢复、凭证隔离、公约校验、管理员权限/并发审批/手动添加/撤销、代理鉴权/拒绝/超时、重连选择/离线回退/重启持久化、桌面和手机交互。生产探针使用隔离测试记录并清理，不伪装成完整游戏客户端真机验收。
