# 邮件与账号验证候选部署说明

2026-10-03 候选说明。2026-10-04 已获 App / Web / Go 发布授权，正式版本 App 2.0.15（21500）、Web 2.0.21；实际上线结果以对应发布记录为准。范围：Go、Web、Android；游戏 Core 的现有注册验证码投递协议复用，本轮不替换游戏插件。

## 发布顺序

1. 获授权后备份数据库、现有应用链接与服务配置、SMTP 加密密钥，记录当前账号/订单/委托/注销/白名单及旧邮件队列数量。
2. 执行新增迁移 `032_mail_identity_support.sql`；旧账号 game_verified 默认 true，不修改身份绑定、权限记录、订单、白名单或注销状态。
3. 发布兼容新结构的 Go 与 Web 候选，在新邮件系统填写 DM、客服 SMTP/IMAP 和内部系统发信信息。新邮件通道缺少凭据时保持关闭，邮箱注册明确返回 MAIL_NOT_READY；现有账号可正常登录。首次保存 DM 配置前，原审核与管理通知继续使用旧 SMTP；保存 DM 后改由 DM 发送，显式停用不回退旧通道。
4. 客服收件默认只处理启用时间之后的邮件。首次“导入已有邮件并发送收件回执”是明确选择，不能自动勾选。配置初次同步基于接收时间，避免启用和第一次连接之间的来信遗漏。
5. 用专门测试邮箱验证：DM 注册验证码、Help 系统转交的 From/Reply-To、客服直接收件、12 位编号回执、玩家回复归并、客服人工回复、附件以及内部备注不外发。
6. 用测试新账号验证 App/Web 注册、退出/登录、游戏验证、错误验证码及跨账号拒绝；对旧账号确认正常登录和超级管理员权限，普通管理员确认仅工单访问。
7. Android 正式交付须提升版本、核对原发布签名并进行真机覆盖验证。当前 debug APK 不作为自动更新包。

## 数据保留与回退

- 新旧账号均是真实账号；未验证账号不会在失败、登出或升级时删除。
- 游戏验证只绑定权威 UUID，不改游戏准入、钱包和历史交易。
- IMAP 只读同步，不移动、删除或标已读；不支持的邮件显示人工查看提示并留在原邮箱。
- 关闭收件暂停同步，保留游标；关闭 SMTP 通道暂停对应邮件发送。不要删除队列作为恢复手段。
- 已创建未验证账号后，不能直接切回不理解 nullable UUID 和验证状态的旧 Go。优先前向修复；必要时暂停注册和邮件 worker，保留账号、工单、邮件游标、密钥与队列，由验证过的新版本恢复。
- SMTP 结果未知可能重复投递，稳定 Message-ID 辅助客户端去重；不能把“SMTP 已接收”当作收件箱送达证明。
