## 故障与修复

管理后台测试邮件长期处于 `PENDING / attempts=0`。线上 MariaDB 10.5.29 对领取语句 `FOR UPDATE SKIP LOCKED` 返回 1064，工作器无法领取任务；本机 MariaDB 11.8 的原验收没有暴露这个版本差异。

现在使用普通行锁。领取事务结束后才执行网络发送，保留发送租约、重试退避和尝试次数校验；旧发送者不能提交新租约的结果，已接收邮件不会重复领取。工作器新增非空队列错误的结构化日志，便于定位领取失败。

首次诊断还发现 465 端口使用 STARTTLS，以及收件邮箱多写了一个数字。用户随后确认目标邮箱 `489711929@qq.com`，当前已保存配置版本 8：`smtp.qq.com / TLS / 465`、用户名及发件人 `xiwanzi@vip.qq.com`。此次发布保留这份配置和原加密授权码；以生产保存的授权码执行 Go SMTP 认证成功，没有重新写密码。
