# 工单工作区效率验收

2026-10-04，基于 Web 2.0.21 与已接通的邮件工单。候选 Web 2.0.22；本记录中的浏览器操作使用回环地址、随机隔离数据库与合成邮箱，未给真实玩家发信。

## 改动与原因

旧页在 1440×900 下从 y=327 才开始工单区，回复框下沿 y=924、整页高 1070，必须滚页面才能提交。现在取消工单页的居中最大宽度、装饰标题、统计卡片和站点页脚，默认 64px 全站导航图标栏；状态数量收为一行筛选。离开工单后恢复普通后台布局。

- 工单区从 y=94 开始，1440×900 时尺寸 1376×806，约占视口 85.6%；正文可视高度由 181 增至 493px。1920×1080 时工作区约占 88.3%。
- 列表与对话独立滚动，回复框固定在工作区下方；资料默认收起，桌面可展开侧栏，窄屏使用可关闭抽屉。
- 状态、指派、由我处理、标记解决和相邻工单切换前置；输入即搜索，提供类别、负责人范围、清空筛选和草稿标记。
- 邮件回复与内部备注明显区分；按钮显示发送后的状态，可选择成功提交后下一条。失败或版本冲突保留草稿且不跳转。
- 修复重复点击当前工单导致详情清空不再加载；忽略旧工单的延迟响应；恢复读取成功不会抹掉提交失败提示。
- 结果未知的提交按工单与操作内容保留原请求 ID / 原版本，即使刷新到新版本再重试也不重复发信。
- 实测发现中文搜索会在 ASCII 工单号/邮箱字段上触发 MariaDB 1267；查询时显式转为 utf8mb4，不变更表、数据或邮箱设置。

## 验证结果

- Web 71 项既有测试与生产构建通过（保留原有大包提示）。
- Go 定向 race：中文/emoji/编号/邮箱/游戏 ID/大小写/字面量搜索，以及现有邮件工单线程、权限隔离与幂等回归通过。
- 实际浏览器流程：领取、分配给我、搜索空结果、分类重置、跨工单/公开与内部草稿隔离、内部备注不发信、发送并解决及进入下一条、资料优先级保存、导航折叠、相邻切换通过。
- 断网失败后保留草稿；重试使用同一请求 ID。额外模拟“后端提交成功而响应丢失”，刷新后再次提交仍只有一条回复及一个发信任务。
- 并发版本冲突后草稿保留，手动重试成功；Ctrl+Enter 提交通过。旧工单详情延迟返回不覆盖新选择。
- 客服专用角色仅显示工单导航；其余管理权限未扩展。
- 浅/深色、桌面与移动资料抽屉、键盘焦点/Tab/Escape、移动返回列表、离开工单恢复布局通过。
- 1920×1080、1440×900、1366×768、1024×768、768×1024、390×844、320×667、390×480：无整页横/纵溢出，提交按钮完整可见且未被导航遮挡。390×480 是缩短视口验证，不替代真机软键盘实测。
