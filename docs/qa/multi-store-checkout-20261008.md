# 跨店结算与优惠券页验收

2026-10-08，工作区 `.worktrees/catalog-scale`，分支 `xiwanzi/multi-store-checkout`。本记录保留本机验证证据；已于 23:27 上线，见[上线记录](../deployment/deuterium-2.0.21-live.md)。

## 实现

优惠券页面恢复原正文色金额/门槛、原蓝色提示；商品卡片等其他优惠展示不变。购物袋一次确认总额，按店分别生成独立订单、托管引用、成交快照和游戏邮件。各店优惠独立计算，同一张券整组最多使用一次，最大权重分配获得总优惠最大的合法组合。退款、返券和投递重试均按店铺订单进行。

合并订单在一个数据库事务内校验、预留库存/券，所有店铺资金预留完成后才投递。明确扣款失败会取消未扣订单并补偿退款；未知结果沿用原 Core 操作 ID 查询，不重扣。投递失败保留该店订单以便原有重试/退款，其他店继续投递。补偿退款明确失败时保留真实 HELD 订单及独立退款入口，操作返回 `CHECKOUT_REFUND_REQUIRES_ATTENTION`，不声称全部退款成功。

App 收到多店结果后缓存所有订单并打开订单列表，持久化恢复读取全部 `resourceIds`。Web 展示总额、各店金额/优惠、各订单入口，并恢复整组结果。原单店返回结构保持；增加的组字段见 OpenAPI。资金层仍是每店独立托管，用户侧一次确认，并非改用共享托管余额或新游戏插件。

## 验证

- Go 全包测试通过；43 项资金/优惠相关父用例通过（含 6 项新跨店父用例及其子场景）。隔离 MariaDB 验证：两店最优券分配、独立金额/邮件/退款/返券、并发同键仅创建两单和一个操作、旧报价重用拒绝、库存/改价/过期整体回滚、扣款未知恢复、第二店失败补偿及补偿未知恢复、补偿失败后独立退款、免费/部分免费订单、单店投递失败重试且不再次扣款。既有单店、市场、委托、退款与优惠回归通过。
- 最大优惠分配用 1–5 店、0–5 券的随机小矩阵，与穷举所有合法分配比较，共 900 组，通过。沿用原价/折扣/门槛/舍入函数，不另写商品定价规则。
- 实际隔离接口的 `CheckoutQuote`、`OrderCreationResult`、`OperationLookup` 按更新后的 OpenAPI 校验通过。
- Android **169 项 JVM** 通过；Debug、测试包、performance（R8/资源压缩）构建和 lint 通过。正式包 `com.deuterium.app.uilab`，2.0.21 / 22100；签名与线上一致。
- 原生 Debug 同源页面：优惠券卡浅色黑字/深色白字实际像素检查、27.00 合计一次确认、7.00 和 20.00 两个店铺订单分别出现在历史、购物袋清空、模拟重新读取持久化操作恢复两单且 POST 仍只有一次，全部通过。初版测试夹具缺少商品必填字段、按钮定位误中同名标题，已修正夹具与选择器后通过，生产页面未为迁就测试而改动。
- Web **75 项测试**及生产构建通过。Playwright CLI 驱动 Chrome：各店报价、一次付款、独立订单入口、断线恢复读取两笔订单、付款 POST 仅一次通过；390 px 无横向溢出。仅 QA 页 favicon 404，无页面脚本异常。

本机截图和日志在 `C:/DeuteriumAPP/delivery/Deuterium-2.0.21/` 与 `.tools/shop-v221-*`。本轮没有用真实余额购买测试商品，也没有产生真实游戏测试邮件；Core 资金/邮件结果使用隔离可信凭据测试桩。用户真机手感和真实游戏客户端收件不冒充已经验收。

## 发布边界

配套 App 2.0.21、Web 2.0.30 和 Go 共同更新，无 schema 迁移、无游戏插件变更。发布前备份配置/数据库、核对进行中资金操作为 0；保留真实新订单。回退前必须确认没有未完成的合并付款，旧程序不具备执行新的组操作的能力；不得还原整库覆盖新增业务。
