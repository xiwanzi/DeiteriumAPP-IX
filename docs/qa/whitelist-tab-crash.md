# 白名单管理切换白屏回归

2026-09-13，Web 2.0.17。本轮只修复管理网页，后端、申请站、Android 与游戏插件沿用线上版本。

## 原因与修复

在 Web 2.0.16 组件中，用空待审列表和非空白名单列表复现：申请记录 → 当前白名单 → 申请记录，浏览器报 `Cannot read properties of undefined (reading 'join')`，React 根节点清空。

两类列表共用 `data`。切换时先使用新的视图渲染旧数据，随后 effect 才清空旧数据；白名单记录没有申请的 `interests` 字段，导致渲染异常。现在响应携带完整查询路径，只有与当前视图、搜索、状态及分页一致的数据才能显示；保留原请求代次校验，避免晚返回的旧请求覆盖当前结果。

## 本轮验证

- Chromium 驱动实际 React 组件，使用隔离的合约数据，没有操作生产申请或玩家。
- 空申请列表往返切换 12 次、非空申请列表往返切换 12 次、延迟 200 ms 下快速往返 6 次，共 30 次；无未捕获异常，页面根节点保持存在。
- 已移除/待审核摘要快捷入口、状态筛选、申请详情弹窗通过。
- 人为保持旧白名单请求，在新申请请求完成后才释放旧请求：当前页面仍显示申请记录，没有误显示白名单数据。
- 筛选切换后等待响应期间，不显示上一筛选条件下的行。
- Web 68 项现有测试通过；生产构建通过，仅保留既有的产物体积提示。
- 上线后核对公网正式产物哈希，再以浏览器内隔离 API 响应驱动完整生产构建，往返切换 10 次通过，页面显示 Web 2.0.17。

原版本的问题已在真实浏览器中复现；此前申请/审批流程验收未覆盖非空白名单回到申请列表的这一切换。本轮补齐该路径及延迟响应验证。
