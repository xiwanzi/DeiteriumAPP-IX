# 2.0.0 商品目录、玩家市场与报价验收

日期：2026-09-08。工作区 `test-release-v2`。这是本机 SQL 与 HTTP 验收，未据此宣称生产付款、担保、邮箱领取或真机体验已通过。

## 本阶段行为

- 官方店铺、品牌、分类和首页可由授权管理员维护。平台管理员通过新增 `POST /api/v1/admin/stores` 创建正式店铺；请求沿 `StoreEditRequest` 去掉 `expectedVersion`，返回 201 `StoreView`。空库不生成示例店铺或商品。
- 商品创建和修改保留草稿；显式发布后公开目录才出现已发布版本。公开标题/简介/品牌搜索也只使用已发布内容。下架、归档和库存调整校验当前版本及权限，库存调整不会发布其他草稿修改。
- 市场采用固定六分类；玩家只能修改自己的商品。发布、编辑、下架和重发均持久化，公共列表只返回 active 且有库存的内容；本人管理列表可看下架内容。
- 购物袋以整个购物袋的 version 处理数量变化和移除；写入时重新检查商品可见性、实时库存及单笔限购。
- 报价金额来自服务端已发布价格和产品版本，以整数精确计算信用点的小数位；报价保存五分钟，不预留库存或扣款。`Idempotency-Key` 可显式提供，未提供时按相同正文和五分钟窗口去重。
- 当前 `POST /store/orders`、`POST /market/orders` 明确返回 503 `CAPABILITY_UNAVAILABLE`；没有扣款、冻结或伪造订单。完整交易编排是下一阶段。
- 所有商城/市场资产在同一业务事务中绑定。商品草稿和已发布图片使用不同绑定，已绑定图片不能被上传者直接删除；发布从已验证草稿绑定晋升，支持多个有权商家共同编辑。
- 商家权限通过 platform.admin、显式 store.manage 或店铺成员权限检查。成员只获 PRODUCT_EDIT 时不能发布；权限撤销后不能读取管理内容。创建店铺和管理成员仍有独立管理权限校验。

## 数据与协议

`internal/store/migrations/011_catalog_v2.sql` 新建目录记录、店铺成员、幂等结果、购物袋/条目和报价表；无种子数据，不修改 001。011 已向主任务确认冻结，后续交易扩展使用新迁移。

写入使用服务端身份、事务、唯一幂等键和乐观锁。相同身份/请求键/正文重试返回原结果；换正文或业务作用域返回 `IDEMPOTENCY_CONFLICT`。正文有 512 KiB 和 32 层硬上限，拒绝重复 JSON 键、未知/缺失字段、无效金额、重复附件、非法类别与交付方式。引用的图片目的、状态、权限与绑定在数据库侧核实。

路由入口为 `Server.registerCatalogV2(mux)`，由主任务在 server.go 挂载。本阶段未修改 server.go。

最初阶段交付引用来自 Core 精确版本；本日后续已补正式交付模板管理，详见 [模板管理增量](../contracts/delivery-template-management-v2.md)。当前发布与新报价必须使用后台批准的模板 ID，并核对 Core 精确 revision/摘要/数量/编码/背包域/兼容范围及未归档 HEAD；不接受控制台命令或客户端物品字节。模板存在仍不代表付费邮箱已就绪。

本日管理端兼容增量：MerchantProduct 增加可选 `draftImages`，实际服务始终从 PRODUCT_DRAFT 的当前授权绑定签名读取，支持多编辑者图片；已发布 images 仍单独从 PRODUCT_PUBLISHED 取得。不会让浏览器携带上传者 ID 绕过素材接口权限。

## 本次验证

| 验证 | 结果 |
| --- | --- |
| `go test -race -tags integration ./internal/httpapi ./internal/store -run Catalog -count=1 -v` | 首阶段 10 项通过；追加模板验证后 11 项通过，无竞态报告 |
| SQL 环境 | 显式回环 MariaDB 33717；每项集成测试创建随机 `deuterium_test_*` 库并清理自己的库；不读取生产 DSN |
| 实际响应 OpenAPI 校验 | 7 类通过：StoreProduct 列表/详情、MerchantProduct、ShoppingBag、StoreView、CheckoutQuote、MarketListing |
| 编译及静态检查 | store/httpapi 编译与本次相关单元测试通过；提交前运行 go vet 与差异空白检查 |

关键证据包含 12 个并发同键发布仅生成一条记录、同一版本两个下架动作只有一个成功、跨玩家修改与盗用图片拒绝且不留部分记录、绑定图片删除拒绝、草稿价格/搜索内容不泄露、购物袋重复请求不加量、报价重试不增加记录/扣库存、未开放付款明确失败、店铺成员不能自行升权、首页首次配置同键重试保持身份和版本、Cookie 写请求缺 CSRF 拒绝。

实际 SQL 测试发现并修复了 `INSERT IGNORE` 重复键共享锁再升级造成的死锁：幂等记录改用无副作用的 `ON DUPLICATE KEY UPDATE` 取得互斥行锁。另修复了首页第一次 PUT 与后续重试在创建/编辑路径间切换导致的幂等作用域不一致。

响应样本只包含隔离合成身份与本地签名的无效测试资产地址；未向对象存储上传测试物品或向真实玩家发送信息/交易。需要复核时设置绝对目录 `DEUTERIUM_CATALOG_SAMPLES`，运行上述测试后将 `responses.json` 交给 `scripts/validate_contract.py`。
