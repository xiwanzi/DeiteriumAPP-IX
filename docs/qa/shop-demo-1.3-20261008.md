# 商城演示 1.3：货币符号与优惠状态

2026-10-08。用户要求去掉漂移的“信用点”尾标，使用人民币/日元通用的 `¥` 符号；信息流同时展示普通、促销、可用券状态，并自动优选一张券放在卡片中间。

## 已实现

- 商城价格使用同一段文本渲染 `¥` 与金额，避免独立尾标位置漂移。首页大卡、信息流、商品价格、购物袋和优惠券金额同步；只改展示，不改变账务金额单位或结算协议。
- 演示商品混排普通价、8 折促销、单券优惠、促销叠券四种示例。原价/有效价由本地规则生成，真实商品定价没有改动。
- 卡片名称与价格之间展示促销直降、优选券名称及条件；主价显示券后价或促销价，原价删除线保留。点击券条查看券名、门槛、叠加条件和单件券后金额。
- 演示内置满 100 减 20、满 200 减 40、9 折（封顶 30）、无门槛减 5 四张券，仅适用于指定演示商品。每张商品卡比较单件应付价，选择真正最优惠的一张；同优惠优先较早到期，再按 ID 稳定选择。
- 优选检查有效期、商品/店铺适用范围、门槛、能否叠加商品促销、优惠封顶。按分计算、单件四舍五入，与既有 Go 计价口径一致。不叠加券不一定优于商品促销，不会为了展示券而选更贵的结果。

`DemoCouponPricing.kt` 位于 `shopDemo` source set，不进入普通正式包。共用界面只消费可选的 `offerPreview` 展示信息，缺失或不一致时不显示券价；预估值不作为结算金额提交。正式商品列表若需要此能力，仍须服务端按当前账户授权返回并处理过期刷新，本轮没有实现或发布该生产接口。
