# 主动建单与管理员游戏 ID 修改验收

2026-10-04（UTC+8）。本轮基于已上线 Web 2.0.23，候选 Web 2.0.24；所有写入验收均在回环隔离数据库，Core 名称解析使用合成在线快照，SMTP 仅由本机回调捕获。

## 功能结果

- 工单工作台新增“新建工单”，填写邮箱、主题、类型和正文后“创建并发送”。首封使用现有玩家支持人工回复模板，主题及正文顶部带 12 位工单号；只入队一封 ENTERPRISE/TICKET_REPLY，没有自动收件回执。默认由创建人负责、等待玩家回复。
- 没有平台账号的邮箱也可建单；已注册邮箱只作资料关联。玩家回复按原邮件线程接回原单并重新待处理，不补发回执；玩家尚未回复时也可继续发信。
- 账号与权限新增超级管理员专用“修改游戏 ID”。修正未验证账号填写的游戏名；已验证账号改名必须由 Core 确认仍属于原 UUID。更新登录别名、撤销目标账号旧会话及旧游戏验证码；资产、内部身份、昵称字段、QQ、邮箱、权限和验证状态保持。
- 前端网络结果未知时锁定原请求内容并允许确认重试；成功请求返回原结果，不重复建单/发信/改名。游戏 ID 版本冲突先刷新当前账号资料，再由管理员核对重试。

## 本轮验证

- Go notify/httpapi/store 普通测试与 vet 通过。
- 6 项定向 race 通过（27.115s）：两项主动建单、两项管理员改名、原游戏验证门禁、原邮件归并/权限回归。另行执行新接口网页 Origin/CSRF 拒绝测试通过。
- 主动建单：401/403、无效/注入/系统邮箱、通道关闭、加密失败后无残留、并发 8 次同键仅 1 单/1 消息/1 邮件/1 审计、重试内容冲突、已有账号关联通过。
- 实际邮件渲染：首封是“Deuterium IX 玩家支持”、主题/HTML/纯文本均有编号、没有虚构引用、没有自动邮件标记；未收到玩家回复前的第二封引用首封成功；玩家回信进入同单，没有 TICKET_CREATED；其他邮箱不能并入。
- 改名：仅超级管理员、不可改自身、保留系统名称/格式拒绝、未验证改名不授予验证、已验证 Core 同 UUID 改名成功、其他 UUID 拒绝。新名实际登录成功，旧名失效，QQ/邮箱登录别名保留，目标旧会话 401。
- 改名数据：userId/playerRef/UUID/密码/自定义昵称/邮箱/验证状态保持；20.00 的合成交易原支付方及快照不变。成功后 Core 离线仍可同键重试且审计不重复。旧验证码不能覆盖新名，滞后的旧名称验证码签发拒绝；两账号并发抢同名仅一个成功。
- Web 71 项测试与生产构建通过（原有大包提示保持）。OpenAPI YAML 解析通过。
- 浏览器实际操作：新建并打开工单、生成唯一带编号邮件、继续回复、账户重名提示、修改未验证游戏名、新旧值反馈，普通工单管理员可建单但不见账号管理入口。
- 模拟“服务端提交成功、浏览器丢失响应”，建单与改名均沿原键恢复，无重复。表单草稿和收件邮箱保留，未知结果不能改写请求内容。
- 新建表单 1440×900、390×844、320×667 没有横向溢出，提交按钮可达；改名表单桌面/手机、两种弹窗浅深色检查通过。小屏长表单在弹窗内滚动。
