# 同 UUID 正版改名：本机候选验收

后续状态：本候选已追加[事件驱动架构修订](uuid-name-event-architecture-20261013.md)，下文定时名字扫描、App/Web 高频拉取及通用响应投影仅记录初版实现，不再是最终候选行为。

日期：2026-10-13。状态：已实现、隔离测试及组件构建通过；未推送、未合并、未部署。没有改动真实玩家身份、资产或线上进程。需求边界见 [同步契约](../contracts/uuid-name-sync.md)。

## 实现范围

| 入口/组件 | 行为 |
| --- | --- |
| Go 登录 | 当前正版名解析到原 UUID，仍须原平台密码；邮箱/QQ 可继续使用。旧名字被他人使用时按官方 UUID 区分，不转移账号。 |
| 游戏在线发现 | Core 在线状态发现新名字，Go 官方核验后事务更新；每 10 秒检查、单 UUID 失败冷却 1 分钟。离线缓存不能作为改名证明。 |
| 身份及权限 | 保留 userId、playerRef、UUID、密码、邮箱、QQ、昵称、有效会话、头衔和资产；更新游戏 ID、相应登录别名、白名单与头衔目录的名称字段。 |
| App/Web/游戏聊天 | 按稳定引用更新联系人、已加载消息头、资料及会话显示；会话、关注和通知偏好使用稳定标识。正文、时间、未读状态及声音时序保留。 |
| 商城/账单/委托 | 输出时按稳定玩家引用投影现名；不改不可变交易快照、金额或自由文本。 |
| Core/公会/领地 | 持久增量游标、单调名称版本；公会按 UUID 更新，旧离线种子和迟到登录观察不能覆盖新名字。公会关系、领地和其他数据保持。 |
| Cloud/Sparkle | 同 UUID 刷新正版名称证明；复用原 Cloud 身份、账号、绑定、模型选择和 ACL。 |
| 启动器 | 即使 token 尚有效，启动前也读取官方 profile 并核对 UUID，更新缓存名字。 |
| Mail | 按 UUID 联结最新登录名称，更新发送名单/已领取名单的显示及搜索；发送时名单、正文和领取状态保持，旧活动缓存不能回写新名。 |

名称增量的历史名字与序号保持成对，不对增量日志再次应用当前名字投影。慢核验结果使用观察开始时间防回退；同名的新核验也推进时间栅栏。

## 其他游戏入口审计

- 原生玩家名、铭牌/TAB 与现有 MMO 显示使用当前连接的 GameProfile；重新正版登录后获得新名字。
- Gateway 白名单资格、上次子服和同步存档以 UUID 关联；PVE 进度与领取归属同样使用 UUID。
- XConomy 的 `PlayerConnection.onJoin → DataLink.newPlayer → SQLCreateNewAccount.selectUser` 按 UUID 找到余额账户，名称不同时更新名称并同步缓存，不建立另一份余额。
- Mail 最新名称来自实际加入服务器的已认证玩家事件；只在 App 登录、尚未重新进服时，Mail/第三方插件自身的登录名称缓存可能要等下次进服才更新。
- 自由输入的署名、聊天正文、订单历史原文与历史审计描述不是结构化玩家名字，不做全局字符串替换。

这份审计针对当前已知组件，不把未接入的任意第三方插件视为已自动兼容。
