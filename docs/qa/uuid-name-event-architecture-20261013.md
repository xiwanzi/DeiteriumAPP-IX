## 六项修订结果

| 问题 | 最终行为 |
| --- | --- |
| 正版网络等待占据密码名额 | 外部名称解析独立限制为 8 个并发、8 秒超时；密码校验/升级仍限制 2 个计算名额，计算结束立即释放。网络与事务不占密码槽。 |
| 公会故障拖住 Core/广播 | Core 先更新本地已核验名字、分包广播并提交自身游标。公会从本地名字状态消费，使用独立持久游标、工作线程和退避重试；失败有日志。 |
| 在线快照逐人开事务重复写库 | 进出服主动通知现有 Core 连接；Go 按 UUID、名字、会话代次比较变化，只有变化才用一个事务记目录。退出保留最近出现时间，跨服退出不会覆盖另一节点目录。Core 自身在线租约刷新改为单条批量心跳。 |
| App/Web 全量高频刷新 | 移除固定 4 秒会话刷新。初次/重连取得基线，收到事件后读取单个会话；名称和注销增量独立更新，不串行挡住联系人。Web 全站复用一条 socket；失败刷新按资源合并并退避。游戏客户端名字只在会话初始化补齐，之后接收 Core 推送。 |
| 任意响应 JSON 遍历改写 | 删除 HTTP/WebSocket 的通用名字投影。公共聊天及引用在数据读取处按类型批量解析玩家名字；私聊发送人复用原 SQL 身份联结。交易只投影明确的参与方展示字段，原文、金额、签名与存储快照不改。前端在展示边界映射名字，未变对象保留引用。 |
| 一个变化唤醒所有连接 | Hub 按公共消息、用户/会话、名字、账号和配置订阅；合并唤醒时保留全部变化原因。私人消息与会话变化不唤醒无关账号。公共消息分页追赶仅唤醒当前订阅者。 |

正常空闲状态下没有名字扫描任务；名字队列只处理已认证会话变化及尚未成功的观察。保留必要的连接心跳、每分钟在线名单校准、每分钟消息漏投补偿，以及失败任务退避。这些校准不再触发无变化的名字查询或逐人目录写入。
