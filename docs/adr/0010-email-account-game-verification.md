# ADR 0010：邮箱账号与独立游戏验证

状态：Accepted（2026-10-03，用户本轮已选择方案二）。

## 决定

注册使用游戏 ID、任意有效邮箱、邮箱验证码和密码。邮箱验证码只证明邮箱的控制权，创建真实 `identities` 记录并预留登录别名；`server_uuid` 为 NULL，`game_verified=false`。登录成功后 App/Web 进入专门验证页，补充 QQ 并使用 Core 投递的游戏内验证码完成绑定。

本决定覆盖 ADR 0003 中“注册必须同时绑定服务器 UUID”的时点要求。ADR 0003 的身份权威规则继续适用：玩家不能自报 UUID，游戏 ID/QQ/邮箱/中文昵称都不是资产权威。完成绑定不改变账号 ID 和 playerRef，不合并账号，不改变游戏白名单。

注册前已存在的账号保留当前所有业务状态，迁移后默认已验证；原游戏 ID/QQ 登录保留。新邮箱可作为登录与找回密码的入口。昵称独立可修改、可重复、支持中文；头像详情同时显示昵称、游戏 ID 和 QQ。

## 权限与邮件

既有 `platform.admin` 在产品中显示为超级管理员，保留全部权限。新增 `support.manage` 显示为管理员，只能管理工单；存在该权限但没有 `platform.admin` 时，其他后台权限检查拒绝。账号管理保留最后一名超级管理员保护、禁止自行更改和角色撤销会话失效。

自动通知、验证码、工单受理及白名单结果走 DM；人工回复、官方手动邮件走企业邮箱。原 SMTP 配置/密钥及原审核通知数据保留，不在 DM 不可用时私自回退旧发件通道。

用户最新明确要求工单以客服邮箱收件为权威入口。直接玩家来信及未来 Help 的系统邮箱转交均在收件后建单；Help 转交使用登录玩家邮箱作为 Reply-To 并校验一次性服务端证明。没有在线对话或玩家工单列表。工单编号为 UTC+8 日期 YYYYMMDD 加四位随机数字；收件后通过 DM 模板立即入队回执，人工回复使用客服企业邮箱。内部备注仅后台可见、不发邮件；验证页只提供邮件求助入口。

## 代价

新增未验证账号意味着旧版本后端不能直接回退；旧版客户端注册也需要升级为邮件注册。游戏 ID 作为登录别名预留后，重名和占用需要通过登录/找回或工单处理。服务器 UUID 的唯一性和资产归属仍在游戏验证事务中检查。

详细边界、回退与验证见[实施计划](../plans/mail-identity-support.md)和[接口契约](../contracts/mail-identity-support.md)。
